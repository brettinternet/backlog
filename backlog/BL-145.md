Phase 1 of BL-103: the internal/changes model and local git links (worktree, branch, and landed stages), shown on every surface without network access. See BL-103 and docs/changes.md.

## Acceptance criteria

- [ ] Worktrees, local and fetched branches, and first-parent landed commits link to the item they name, read from .git without network access
- [ ] The Changes tab, the list column, and History groups show each linked change at its furthest stage
- [ ] has:change matches items with a linked change
- [ ] bl changes ID --json and MCP changes return the same changes and provider statuses
- [ ] ys copies the SHA of a History commit row, and the shipped gh, lazygit, and nvim action examples run only on a linked change

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change
