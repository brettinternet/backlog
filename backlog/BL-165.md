A tour goes stale as soon as the change gets a new head, so a reviewer returning after the author pushes fixes loses it. Instead of hiding a stale tour, map each step from the tour's ref to the current head through the diff between them, like outdated review comments on a forge: unchanged lines move to their new position, edited or deleted lines are marked outdated. Costs no agent tokens. Mapping runs on the detail worker, never the update loop (D14).

## Acceptance criteria

- [ ] When the change's head differs from the tour's ref and the ref is still reachable, each step whose line is unchanged between ref and head renders at its mapped line, on its side, as a current step does
- [ ] A step whose line was edited or deleted since ref is marked outdated, shows its line as of ref, and ]t/[t still visit it without moving the cursor onto an unrelated line
- [ ] A banner names the tour's commit, the current head, and how many steps are outdated; a ref that is no longer reachable (rewritten history) shows stale as today
- [ ] A step on a file renamed between ref and head maps to the new path
- [ ] Mapping reads git objects only, is cached by tour ref and head, and stays within the design.md section 11 budgets
- [ ] docs/tui.md, bl instructions tours, and design.md D43 describe carried-forward tours

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change
