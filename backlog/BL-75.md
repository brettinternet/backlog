`hook.finished` records outcome, exit code, duration, and result, but drops everything that explains a failure. `internal/hooks/runner.go` computes `execution.message` (the refusal reason: unexpandable placeholder, empty run, invalid timeout, malformed result) and captures stderr in a `limitedBuffer`, then builds the finished event without either. Only `before` hooks surface their first stderr line, as the rejection message. Actions return `message` to the caller but not in `action.finished`.

So a `refused` hook says nothing about why, and a failed detached hook leaves no trace of its error anywhere. Debugging means re-running the command by hand with a reconstructed environment.

Add one optional `message` field to `hook.finished` and `action.finished`: the refusal or exec error, or for a nonzero exit or timeout, the last few lines of stderr. Bound it (for example 1 KiB, terminal control sequences stripped per D21) so the 16 MiB event limit and log size stay unaffected. Stdout is not included; it is the result channel.

## Acceptance criteria

- [ ] A refused hook.finished event carries the refusal reason (for example the placeholder that could not expand)
- [ ] A failed or timed-out after hook carries a bounded tail of its stderr; ok outcomes and before hooks are unchanged
- [ ] docs/events.md and docs/automation.md specify the new field, its bound, and that it is display text, not a contract for parsing
