`bl` already passes `WORKLEASE_HOME` and `WORKLEASE_PROFILE` through to Worklease (design.md §9), and native item keys are portable: `worklease key --provider generic --source github.com/brettinternet/backlog --item BL-1` returns `coordination:generic:5e85…` with `identityScope: portable`, which `worklease server init` admits by default. So claims across hosts should already work when every clone shares the `origin`-derived project ID and selects one remote authority. None of it is tested or documented.

Verify it against a real `worklease serve` (Worklease 1.10.x) before BL-70 builds on it. This doesn't need BL-70 and can be promoted on its own.

## Draft until decided

1. **Host-local IDs.** A project without a usable `origin` gets a host-local ID (design.md §5), so two hosts derive different keys and never contend, without any error. Should `bl` refuse claims or only warn, and how does it learn the authority is remote?
   **Recommendation:** refuse. Acquiring (`claim`, `next --claim`, an active transition) fails with `unavailable` (exit 6) before anything is written, and the message says to set `project.id`. Release and heartbeat still work, so an existing claim can be cleaned up. `bl doctor` reports the same finding. A warning isn't enough: claims that never contend look like they work, and the design fails closed everywhere else. Detect the authority with `worklease --json profile show`, run from the control root with the session environment removed, as every other call is. It is offline and setup-free, and reports `"builtin": true` for local (observed with Worklease 1.10.1). Treat anything else as remote. Run it once per process, only when an acquire needs it, never per row (§11 hazard 11). If the output can't be parsed, refuse rather than guess.
2. **Test placement.** The round trip needs a real `worklease` binary and TLS on loopback.
   **Recommendation:** make it opt-in under `BL_PROVIDER_TESTS=1`, like the other provider round trips. Use a `BL_TEST_WORKLEASE_BINARY` override, as `BL_TEST_BD_BINARY` does for Beads. Run the server and both enrolled homes under the test's temp directory, and keep the default suite on the existing fake CLI. Unit-test the host-local refusal against a fake `profile show` response, since it's a correctness boundary that must not depend on the opt-in run.

## Acceptance criteria

- [ ] Two isolated homes enrolled against one TLS worklease serve on loopback run bl next --claim --start on one project and get different items; bl claim on the other's item exits 7 naming the holder
- [ ] heartbeat renews and bl done releases through --if-claim-id against the remote authority
- [ ] An acquire interrupted by stopping the authority resumes with the same session through exact replay after restart, and never acquires a second item
- [ ] docs/cli.md#coordination shows how to select a remote authority for bl
- [ ] With a host-local project ID and a remote authority selected, claim, next --claim, and active transitions fail with unavailable before writing; release and heartbeat still work; bl doctor reports it
