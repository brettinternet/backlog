Phase 2 of BL-103: a GitHub forge that fetches pull requests through the account queue and links them to items with state, checks, and review. See BL-103, docs/changes.md, and docs/github.md#linked-changes.

## Acceptance criteria

- [ ] A GitHub forge fetches pull requests through the account host queue into a per-repo cache with an updated cursor, and a failed refresh keeps the cached pull requests marked stale
- [ ] A pull request links by head branch, whole-word ID in the title, a closing keyword in the body, or the provider closing references, and shows state, checks, and review decision
- [ ] change:, checks:, and review: match linked pull requests, and hook conditions refuse them
- [ ] docs/github.md names the read App permissions the forge needs as an owner step

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change
