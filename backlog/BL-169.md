Device login uses the `bl-cli-read`/`bl-cli` GitHub Apps, whose user tokens reach only repositories where the App is installed. Org members often can't install Apps, so first-run setup stalls. A `gh` credential helper needs no installation and reaches every org and repo the user can, which matches the `gh` login-once experience.

A. Docs: make the `gh` helper the recommended GitHub setup in `docs/github.md` (and README/examples that show GitHub setup). Present device login as the stricter option for users who want a token that can't write, and state the tradeoff: a `repo`-scoped `gh` token can write, so bl's write gates (`--write`, `allowWrites`) are the only limit on that path.

B. `bl auth login github NAME`: when the account isn't `oauth: true` (or as an offered alternative), detect a working `gh auth token --hostname HOST --user USER` for the configured user and offer to configure the helper instead of starting the App flow. Needs a terminal (consent prompt); never writes credentials, only the helper argv in user config. Verify the principal matches `user` before writing.

BL-170 (draft) covers the alternative of a bl-owned OAuth App.

## Acceptance criteria

- [ ] docs/github.md leads with the gh helper and presents device login as the strict read-only option, stating that a repo-scoped token can write
- [ ] bl auth login github NAME detects a working gh token for the configured user and host and, after terminal consent, writes the gh helper to user config instead of starting the App flow
- [ ] The offered helper is refused when the gh token principal differs from the configured user
