Read the parent epic first. Its Layout (Verdict strip, Overview), Data, Agents, and Register sections are the settled design. This is the foundation the other children build on.

## Scope

- **Read.** Extend the forge `Review` read (`internal/source/github/review.go`, `internal/changes/review.go`) with merge state, check detail fields, reviewer detail, and About facts (see the epic's Data table). Keep it one GraphQL read per pull request, cached by head in `.reviews.json`, and reused for a minute (D43). First, probe `mergeStateStatus` and `isRequired(pullRequestNumber:)` on a live repository and record in Notes whether either needs a preview header. Without them, compute the verdict from `mergeable`, checks, and review decision, and omit `required`.
- **Model.** In `internal/changes`, check state words (`queued`, `running`, `waiting`, `failed`, `timed out`, `cancelled`, `action required`, `passed`, `skipped`, `neutral`, `stale`) map onto the existing rollup categories, so `checks:` queries and current glyphs keep their meaning. A `Verdict` function returns the verdict and ordered reasons from merge state, checks, review, and staleness. It is the one place the strip, the Overview Merge section, the JSON, and BL-177's list glyph get it.
- **Strip.** One line under the change view tabs on every tab, as specified in the epic. Branch and worktree changes show stage, branch, `↑ ↓`, and dirty count.
- **Overview.** Replace the property sheet with the Merge, Checks, Reviews, (existing Draft), About, and description sections. Merge reasons, checks, and reviewers are entries. `enter` on a check opens nothing until BL-178, and its key stays disabled with the reason. `enter` on a review reason or reviewer opens Conversation on that review. `enter` on unresolved threads opens Conversation on the first unresolved thread; BL-180 retargets it to the Diff. `enter` on conflicts or behind opens `!` narrowed to change actions. Passing and skipped checks fold past six checks (`enter`/`za`). Columns drop by width as specified.
- **Agents.** `bl changes ID --detail [--json]` and MCP `changes` `detail: true` add `merge`, the extended `checkRuns` fields, and `reviewers`. Default output is unchanged. `bl instructions workflow` names `--detail`. Text output prints the verdict line and a reason per line.
- **Register.** Record D45 as the epic words it, scoped to what this child ships, and amend the D43 row's pointer.

## Not here

The list glyph and queries (BL-177), check detail (BL-178), threads in the Diff (BL-180), writes (BL-181), polling (BL-182).

## Tests

- `Verdict` table test in `internal/changes`, at the lowest layer. It catches the realistic failures: a stale read showing `Ready`, `UNSTABLE` reading as `Blocked`, a draft reading `Ready`, and reasons out of order.
- Extend `TestForgePullRequests`'s fake server for the new fields, including redaction of check titles and summaries.
- Extend `TestChangeViewReview` for the section order, folding, and `enter` targets.
- Extend `TestEventsMatchCLI` for `--detail` CLI/MCP parity.
