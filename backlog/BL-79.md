Cutting unsound (224 items, 5 milestones) over with `bl import backlog-md --in-place` worked. `bl check` passed on main and v0.2.0, and fidelity spot checks matched. Each gap below was hit on that data. Reports are in /tmp/uns-import-preview.json and /tmp/uns-import.json, and the scratch repro is in /tmp/bl-repro/repro.sh.

1. Backlog.md `references` values are copied into `refs` verbatim, though format.md defines `refs` as URLs or repository-relative paths. In unsound, 8 items listed bare item IDs (`UNS-61`, `UNS-150`) and one listed commit SHAs (`0c32301`). `bl check` reports no findings for either. Item IDs should become `related`, following renumbering like other references. Values that are neither URLs nor paths should be kept somewhere that doesn't claim to be a path, or reported. `check` should flag a ref that is neither a URL nor a plausible path. The merge of `documentation` into `refs` also drops the docs-vs-references distinction that unsound's repo test relied on; document this.
2. `bl set ID related+=A,B` and `blocked_by+=A,B` exit 5 with `invalid-value: related reference at line 4`, though `set --help` says list values are comma-separated. `related=A,B`, `blocked_by=A,B`, `labels+=a,b` and `refs+=a,b` work, and repeated `related+=A related+=B` works. The error's "line 4" points at internal frontmatter, not the user's argument.
3. docs/import.md documents `--in-place`, but the released v0.2.0 (mise `github:brettinternet/backlog@latest`) doesn't have it (`flag provided but not defined: -in-place`), so this cutover needed the primary-main build. The documented quick path `bl import backlog-md --to backlog` fails with `refusing non-empty target directory`, without suggesting `--in-place` when the target is the Backlog.md folder itself.

## Acceptance criteria

- [ ] bl set FIELD+=A,B and FIELD-=A,B accept comma lists for ID fields (related, blocked_by, duplicate_of), and invalid-value errors name the argument, not a frontmatter line
- [ ] bl import backlog-md --to DIR naming a non-empty Backlog.md folder suggests --in-place
