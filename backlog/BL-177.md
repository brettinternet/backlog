Read the parent epic's "List and navigation" section first. It is the settled design. This child makes pull requests reachable and scannable from the list, whether a task links them or they are `github-pulls` items (D44).

## Scope

- **List read.** Add `mergeStateStatus` to `pullsQuery` (`internal/source/github/pulls.go`) and store it in `.pulls.json`. GitLab leaves it empty.
- **List glyph.** The `changes` cell's last glyph becomes BL-176's `Verdict` glyph, using the epic's precedence. Drafts and an unknown merge state keep the checks glyph. The cell width is unchanged. The help overlay legend and `docs/tui.md` list the glyphs.
- **Query.** `merge:ready|unstable|blocked|behind|conflicts` is evaluated from the list read in the projection worker, like `checks:`. Like other change terms, it is refused in hooks. Malformed values are usage errors (query.md).
- **`gp`.** From the list or detail: open the item's furthest open pull request in the change view, or its Changes tab when it has several. When it has none, the action is disabled with the reason.
- **PR items.** Detail on a `github-pulls` item opens in its own pull request's change view. `backspace` shows its item tabs.
- **`J`/`K`.** With a change view open, the next or previous item opens on its furthest pull request in the same tab. An item without one shows its item tabs.
- **Go-to.** `ctrl-p` with `#45` or a pull request URL selects the item showing that pull request (its linking item or PR item), else it says that no item shows it.

## Tests

- `merge:` semantics wherever `checks:` is tested. It catches an unknown merge state matching `ready`.
- TUI key routing for `gp`, PR item auto-open with `backspace`, and `J` keeping the tab, extending `TestChangeView`.
- Fuzz: extend the query fuzz corpus with the new term.
