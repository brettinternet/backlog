After label statuses run in this repository (BL-121), try the Projects v2 path on the same issues and keep whichever works better. A source uses labels or a project, not both (BL-117), and two sources on one repository would list every issue twice, so this switches the `issues` source over rather than adding one.

Needs the owner: create a project for brettinternet/backlog with a Status field of Backlog, Ready, In progress, and Done (GitHub's default board), add the open issues to it, allow `bl-cli`/token `project` scope writes, and run `bl trust` after the config change.

Config: replace `statusLabels` with `githubProject` (owner, number, id, fieldId, `allowWrites: true`), mapping Backlog to backlog, Ready to todo, In progress to active, and Done to done. Statuses: the option IDs, plus `unknown` (backlog) for issues not on the board and `closed`. Set `workflow.start` to the In progress option. Find the IDs with `gh project field-list NUMBER --owner brettinternet --format json`.

Compare the two modes for triage effort, agent start/done round trips, create with status (BL-118), and sync cost (BL-120). Record the decision and the kept config in docs/github.md, and remove the unused labels or project.
