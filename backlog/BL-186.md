## Why

`bl` has some thirty commands, fixed `set` field names, and a query language whose completer already powers the TUI filter bar (`Snapshot.Complete`, internal/query/complete.go), but the shell completes nothing: there's no `completion` command and no `ShellComplete` in internal/cli. People type `bl set 12 status=` and then go look up the key.

## Scope

- Enable urfave/cli v3's shell completion (`EnableShellCompletion`, v3.14.0 pinned) so `bl completion bash|zsh|fish|pwsh` prints a script. guide.md's Install section shows how to load it.
- Dynamic candidates through per-command `ShellComplete`:
  - Item IDs for every ID argument, open items first, with the title as the description where the shell shows one (zsh, fish).
  - `bl set` field names, then values after `=`: statuses the item's source accepts, priorities, labels, assignees, milestones, and IDs for relation fields.
  - Query arguments (`ls`, `next`, `tui`, `events`): the TUI's field and value candidates from `Snapshot.Complete`.
  - Flag values: `--view`, `--workspace`, `--source`, `--status`, `--sort`, `--group`, `instructions` topics, `action` names, and `auth` providers and accounts.
- Completion reads config, the native read cache, and cached remote rows only. It never runs hooks, actions, external adapters, credential helpers, Worklease, or Git, and never contacts a provider, so it's safe in an untrusted project (D16) and needs no trust.

## Tests

- One test per candidate kind through the root command's completion entry point, plus an untrusted project with an external adapter source completing without starting it. Catches a completion path that runs an untrusted program on tab.

## Acceptance criteria

- [ ] bl completion bash|zsh|fish|pwsh prints a working script, and guide.md shows how to install it
- [ ] ID arguments, bl set fields and values, query arguments, and the listed flag values complete from config and cached items

- [ ] Warm ID completion at 10k items meets the bl ls budget (150 ms p95) on the reference host
