Add brettinternet/backlog issues as a second source, so new GitHub issues show up next to native tasks without feeding agent loops until someone triages them.

Needs the owner: create the `ready` and `in-progress` labels on the repository, create a dedicated disposable repository for live provider tests, and run `bl trust`. The user config account `personal` (gh helper) already exists in `~/.config/backlog/config.yaml`.

Config: add an `issues` GitHub source with `statusLabels: {ready: todo, in-progress: active}`. Add `unknown` (Triage, backlog), `closed` (done), and `ready` (todo) statuses, and reuse `in-progress` as the active key. Set `defaults.source: tasks` so agent `bl new` stays native. Verify readiness with `bl next -n 0`, not plain `bl next`, which shows only the top item.

## Acceptance criteria

- [ ] backlog.yaml has an issues source with statusLabels and defaults.source: tasks, and bl doctor --online passes
- [ ] An unlabelled issue appears in bl ls and is absent from bl next -n 0; labelling it ready makes it ready
- [ ] Agent bl new without --source still creates native tasks

- [ ] Live GitHub provider tests (BL_GITHUB_TEST_REPO) target a dedicated disposable repository, not brettinternet/backlog, and docs/github.md says so, so test issues and status labels never enter the real backlog

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change
