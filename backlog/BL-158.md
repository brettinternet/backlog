enter on a Commits tab entry opens that commit's Diff in the change view, as History already does (openCommit), and backspace returns to the parent change's Commits tab with the cursor on that commit. This nests one change view level under another. A single commit's Diff starts with its author, age, and full message (subject and body wrapped to the pane, like git show) above the first file; branch and pull request Diffs are unchanged. Commit gains Body, read with %b for the one commit on the Diff worker, or from the forge for a pull request without a local head. The Commits list stays one line per commit. See the BL-150 conversation: inline expansion was rejected because it would duplicate the Diff tab.

## Acceptance criteria

- [ ] enter on a Commits entry opens that commit's Diff, and backspace returns to the Commits tab with the cursor on the same commit
- [ ] A single commit's Diff, opened from Commits or History, shows its full message above the first file, wrapped to the pane, and branch and pull request Diffs do not
- [ ] Message lines are not entries: j/k, file and hunk jumps, and line anchors skip them
- [ ] Review actions on a single commit's Diff are disabled with the reason (BL-150 drafts anchor to the pull request head)
- [ ] docs/tui.md and design.md D43 describe the behavior

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change
