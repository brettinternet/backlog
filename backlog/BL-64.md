Review of BL-39 found that every Linear refresh (polled each minute) issues one detail query and two relation queries per in-scope issue, after the full list scan (internal/source/linear/linear.go Load/item). A team with ~30 issues already exceeds Linear's hourly request budget, so real teams stay rate-limited and stale. Relations do not bump updatedAt, so they need reconciliation, but design.md and BL-39 call for periodic reconciliation, not every refresh. Fetch detail only for issues new or changed since the cursor overlap, batch detail/relation reads per page, and reconcile relations on a slower bounded schedule, without making unchanged cached rows stale (source.Merge treats unseen rows in partial coverage as stale, so this likely needs an explicit unchanged/retained signal in Delta).

## Acceptance criteria

- [ ] A fake-server test with 1,000 issues shows a steady-state refresh with no changes makes a bounded number of requests independent of issue count, except on the reconciliation schedule
- [ ] A relation-only change is still caught by the next reconciliation and unchanged rows are never marked stale
- [ ] docs/linear.md states the refresh and reconciliation request budget
