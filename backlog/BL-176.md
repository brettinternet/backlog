Read the parent epic first. Its Scope rule, Layout (Verdict strip, Overview), Writes, Data, Agents, and Register sections are the settled design. This is the foundation the other children build on.

## Scope

- **Read.** Add `mergeStateStatus`, `mergeable`, check run `databaseId`, `startedAt`, and `completedAt`, and `latestReviews{commit{oid} submittedAt}` to the forge `Review` read (`internal/source/github/review.go`, `internal/changes/review.go`). It stays one GraphQL read per pull request, cached by head in `.reviews.json` and reused for a minute (D43). First, probe `mergeStateStatus` on a live repository and record in Notes whether it needs a preview header. Without it, compute the verdict from `mergeable`, checks, and review decision.
- **Model.** In `internal/changes`, exact check state words map onto the existing rollup categories, so `checks:` queries and current glyphs keep their meaning. A `Verdict` function returns the verdict and ordered reasons from merge state, checks, review decision, and staleness. It is the one source for the strip, the Merge section, the JSON, and BL-177's list glyph.
- **Strip.** One line under the change view tabs on every tab, as the epic specifies. Branch and worktree changes show stage, branch, `↑ ↓`, and dirty count.
- **Overview.** Replace the property sheet with the Merge, Checks, Reviews, (existing Draft), About, and description sections. Merge reasons, checks, and reviewers are entries with the epic's `enter` targets. Until BL-178, `enter` on a check is disabled with the reason. Until BL-180, `enter` on unresolved threads opens Conversation on the first one. Passing and skipped checks fold past six (`enter`/`za`). Duration drops first as width shrinks.
- **Handoffs.** `enter` on conflicts, behind, or Ready opens `!` narrowed to change actions. When a change action returns, re-read the shown pull request, bypassing the one-minute reuse. Ship the merge, update-branch, ready, and convert-to-draft `gh` examples from the epic's Writes table in docs/automation.md.
- **Agents.** `bl changes ID --detail [--json]` and MCP `changes` `detail: true` add `merge` (`state`, `verdict`, `reasons`), check `status`, `startedAt`, and `completedAt`, and `reviewers` (`login`, `state`, `submittedAt`, `outdated`). Default output is unchanged. `bl instructions workflow` names `--detail`. Text output prints the verdict line and one reason per line.
- **Register.** Record D45 as the epic words it, scoped to what this child ships, including the scope rule, and amend the D43 row's pointer.

## Not here

The list glyph and query (BL-177), the check view (BL-178), threads in the Diff (BL-180), resolving threads (BL-181), and refresh notices (BL-182).
