History shows one group per linked change with its worktree, branch, opened, merged, and closed events and landed commits. The review activity on a pull request (approvals, change requests, comments, review threads) only shows as the current state on the group header, so the timeline can't say who approved when or what the review said.

Outcome: each pull request group in History also carries its review submissions, conversation comments, and review threads as dated members. They come from the per-PR review read the change view already makes (`changes.LoadReview`: description, checks, reviewers, conversation, threads; one redacted read per pull request cached by head for a minute in `.reviews.json`), so there is no new forge query. History reads it only when History opens or `bl history`/MCP `history` runs (D40), never during a list refresh, at most 10 pull requests per load, newest first. Merged and closed pull requests are included, since review history matters most after the merge. GitLab merge requests follow through the same type (their discussions; reviewer states carry no time, so they add no entries).

Non-goals: check runs (noisy; the header already shows the current check state), pushes (landed commits cover them), labels and assignees on the pull request, changing the GitHub review query or the change view's Conversation.

Example under a PR group:

```
  11-17 10:02  review   approved                               alice
  11-17 10:05  review   commented on foo.go:42 · 3 comments    bob
  11-17 10:07  review   commented                              carol
```
