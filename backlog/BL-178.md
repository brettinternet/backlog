Read the parent epic's "Check" layout and "Safety and budgets" sections first. They are the settled design. This child answers "why did this job fail" without leaving bl.

## Scope

- **Check view.** `enter` on a check, in Overview or a Merge reason, opens it one level under Overview. `backspace` returns to that entry. The header shows name, state, duration, group, event, required, and start age, followed by Steps, Annotations, and Log or Output sections.
- **Detail read.** One GraphQL read by check run node ID for `steps(first:50)`, `annotations(first:50)`, `title`, `summary`, and `text`. It runs on the detail worker through the account queue, is redacted and stripped (D21), and is cached by check run ID once the run completes. A running check isn't cached.
- **Log.** For a completed GitHub Actions job (check run `databaseId` is the job ID), fetch REST `/actions/jobs/{id}/logs` on demand when the check view opens. Never send credentials to the redirect host. Stream into a buffer that keeps the last 1 MiB and refuse past 32 MiB, offering `O`. Strip timestamps, split by `##[group]` into steps, and show the failed step, or the last step when none failed. Color `##[error]` and `##[warning]` lines. Cache the result per check run and attempt under the state directory, redacted. Without Actions read, or for a running job, the Log line says why and `O` opens the job.
- **Keys.** `enter` on a step switches the log to it. `enter` on an annotation opens the Diff at its line when the file is in the change. `]`/`[` move between error lines in the log. `/` searches. `m` shows more. `yl` copies the shown step's log. `O` opens the check, step, or annotation URL.
- **Other checks.** Non-Actions check runs show output title, summary, and text as Markdown. Commit statuses show their description.
- **Agents.** `--detail` and MCP `detail` add, for each failing run, its `steps`, `annotations`, and `log` (failed step, capped at 64 KiB) or `logUnavailable` with the reason. Reads are bounded to the first five failing runs.

## Tests

- Log parsing (step split, timestamp strip, error lines, failed-step choice) with a fuzz target, since logs are untrusted input.
- The fake server asserts that the redirect request carries no `Authorization` header, that the 32 MiB refusal holds, and that a secret in the log is redacted in the view, the cache, and `--detail` JSON.
- TUI routing: `enter` on a check, step, and annotation, and `backspace` returning to the entry.

## Acceptance criteria

- [ ] enter on a check opens the check view with its header, Steps, Annotations, and Log or Output; backspace returns to the entry
- [ ] A failed Actions job shows its failed step's log with timestamps stripped and error lines colored, and ], [, /, m, yl, and O work
- [ ] Fake-server tests prove the log fetch sends no Authorization header to the redirect host, keeps the last 1 MiB, refuses past 32 MiB, and redacts a secret in the view, the cache, and --detail JSON
- [ ] Without Actions read, or while the job runs, the Log line says why and O opens the job
- [ ] bl changes --detail and MCP detail return steps, annotations, and log or logUnavailable for up to five failing runs
- [ ] The log parser has a fuzz target, and docs/tui.md, cli.md, and mcp.md describe the check view
