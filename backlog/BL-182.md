Read the parent epic's Freshness section first. It is the settled design. Watching CI finish should need neither `R` nor the browser, and it adds no new cadence.

## Scope

- While a change view or the Changes tab shows an open pull request, re-read its detail on each per-minute forge refresh on the detail worker, through the account queue. `R` reads it at once. Stop when the view closes or the selection moves. Nothing reads a pull request that isn't shown.
- When a shown check reaches a final state or the verdict changes between reads, the status bar shows a notice until the next key: `✕ test (ubuntu-latest) failed`, `✓ checks passed`, `#45 ready`.
- The strip's age counts from the last successful read. A failed read keeps the last data, marked stale (D43).
- The refresh only schedules worker reads. The update loop does no I/O (D14).

## Tests

- With an injected clock and the fake forge: one read per refresh for the shown pull request, none after the view closes or moves, and none for a pull request that isn't shown. These catch a reader leaking after navigation and burning the account's rate limit.
- Notice text on check completion and on a verdict change.
