Phase 6 of BL-103: render CodeTour .tour files that agents write, stored in XDG state per change and shown stale when the head moves. `]t` and `[t` step through the tour in the change view. See the Guided tours section of BL-103.

The usual author is the agent that just did the work, running the claimed loop rather than launched by an action, so tours arrive two ways with one validator: `bl tour ID FILE [--json]` (and an MCP tool with the same shape), or an action or hook that returns `{"tour": "PATH"}` through BL_RESULT. bl never generates a tour.

Format: CodeTour JSON. Its top-level `ref` is the pinned head SHA, and it picks the change: the tour attaches to the item's change whose head equals `ref`, refused when none does. Each step has `file`, `line`, and a Markdown `description`, plus two extensions: optional `criterion` (an acceptance criterion index, so a step can say "AC 2 is met here") and optional `side: "old"` for a step on deleted lines (default new side, matching BL-148's file, side, and line addressing). A step on a line outside every hunk shows that line with context rather than being refused.

Agents learn the format from `docs/schemas/tour.json`, a `bl instructions tours` topic, and a shipped tour-writing action in examples/04-hooks-and-actions.

## Acceptance criteria

- [ ] `bl tour ID FILE [--json]`, an MCP tool with the same shape, and an action or hook returning `{"tour": "PATH"}` through BL_RESULT all store a copy in XDG state for the change whose head equals the tour's `ref`, through one validator; bl never generates a tour
- [ ] A tour is CodeTour .tour JSON (`ref` plus steps with file, line, and Markdown description) with optional per-step `criterion` and `side: "old"`; an invalid tour, or one whose `ref` matches no linked change, is refused with the reason
- [ ] In the change view, `]t`/`[t` step through the tour, with each step's narrative and cited criterion above its line in the Diff, on the step's side; a step outside every hunk shows its line with context
- [ ] A tour whose `ref` differs from the change's current head shows stale rather than landing on other lines
- [ ] Tour text passes D21's control-sequence stripping
- [ ] docs/schemas/tour.json, a `bl instructions tours` topic, and a tour-writing action in examples/04-hooks-and-actions let an agent write a valid tour without reading bl's source; docs/automation.md documents the `tour` result key and docs/cli.md and docs/mcp.md the new command and tool
- [ ] design.md D43 records the `bl tour` command and MCP tool as the tour intake beside action results
