Option C from the GitHub auth UX discussion, parked until needed. Add a third GitHub login path: a bl-owned OAuth App (not a GitHub App) with device flow, no client secret, requesting `repo read:project` (`project` for writes). It gives `gh`'s login-once, no-installation reach to users without `gh` installed.

Tradeoff: OAuth scopes have no private read-only scope (`repo` includes writes), so this gives up the enforced read-only guarantee the `bl-cli-read` App provides; read-only becomes a bl-side policy only. Orgs with OAuth App access restrictions still need admin approval. Revocation still needs a secret, so logout stays local-only.

Changes D17 (in-tree OAuth flows) and docs/oauth.md registrations; needs an owner-registered OAuth App. Revisit only if the `gh` helper path (BL-169) proves insufficient, e.g. users without `gh`.
