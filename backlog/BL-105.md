### Why

The first step of Windows support: a Windows `bl` that builds, passes its tests, and behaves correctly, with claims reported as unavailable until Worklease supports Windows.

### Shape

- **Locks.** One `internal/filelock` package: `flock` on Unix, `LockFileEx` on Windows (`golang.org/x/sys/windows`). It replaces the three copies in `autocommit`, `project/views.go`, and `hooks/events.go`, including their non-blocking and retry behavior.
- **File identity.** Add `internal/cache/stat_windows.go`, using volume serial number, file index, size, and last write time. Windows has no ctime, and the file index needs an open handle, so measure the warm-start cost.
- **Atomic writes (D8).** Rename over a target that's briefly held open (editor, antivirus, indexer) gets a bounded retry on access denied or sharing violations. On failure the original file stays whole and the error is structured.
- **Editor.** Run `$EDITOR` without `/bin/sh` on Windows: split it into argv and append the path, falling back to `notepad`. Unix behavior stays the same.
- **OAuth store.** On Windows, replace the mode-bit check with an owner-only DACL check, and create directories and records with that DACL.
- **Processes.** Detached hook runners use `CREATE_NEW_PROCESS_GROUP | DETACHED_PROCESS`. External and remote source processes run in a Job Object, so a timeout kills the whole tree.
- **Claims.** With coordination configured, claim commands on Windows fail with a structured `unavailable` error that names Worklease, and `bl doctor` reports it. Other commands work normally.
- **Tests.** Unix-only tests (PTY, FIFO, symlink, and shell-script fakes) get build tags or skips that state the reason. Add a `windows-latest` CI job that runs `go test ./...`.

## Acceptance criteria

- [ ] GOOS=windows go build and go vet pass for amd64 and arm64, and a windows-latest CI job runs go test ./... and passes
- [ ] One internal/filelock package replaces every Flock call; a cross-process test proves the write lock, event log lock, and autocommit lock serialize on Windows and Unix
- [ ] On Windows, FileIdentity detects a replaced file and an in-place edit with size and mtime restored, and warm bl ls at 10k is measured on a Windows host and recorded in docs/benchmarks.md with no regression on the reference host
- [ ] A native write while another process holds the target open succeeds after a bounded retry, or fails with a structured error and leaves the original file whole (D8)
- [ ] bl edit and the TUI long editor launch $EDITOR without /bin/sh on Windows, defaulting to notepad, with Unix behavior unchanged
- [ ] On Windows, the OAuth store refuses a directory or record that other users can read (DACL check) and accepts ones it created
- [ ] Detached hook runners survive the invoking console closing, and a timed-out external or remote source process has its whole tree killed
- [ ] With coordination configured on Windows, claim commands fail with a structured unavailable error naming Worklease, bl doctor reports it, and non-claim commands work
- [ ] Unix-only tests are guarded by build tags or skips that state the reason, and none is weakened on Unix
- [ ] The design.md register records the supported platforms, with Windows claims excluded until BL-109
