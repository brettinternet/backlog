## Why

A draft is a status in the `backlog` category, so it is open but never ready (D29). `bl new` always creates a ready item, so an agent's `claim-next` can take an intended draft before `bl set ID status=draft` lands. `bl init` ships no draft status. Imported Backlog.md drafts keep `DRAFT-N` IDs forever, because native IDs never change on promotion, so they sit outside the source prefix and its numeric shorthand.

## What

- `bl new --status S` creates the item in configured status S. An unknown S fails like `bl set status=` and writes nothing. Without the flag nothing changes.
- `bl init` writes a `draft` status (`Draft`, category `backlog`) before `todo`.
- `bl import backlog-md` always writes a draft status, and numbers every draft, active or archived, after the highest task ID in the source prefix, in draft ID order, as `backlog draft promote` would. References to drafts follow the new IDs, and each draft's file report shows its new ID.
- This repository's `.config/backlog.yaml` gains the draft status.
- docs/cli.md, docs/import.md, and design.md D29 match.
