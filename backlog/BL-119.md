GitHub writes cover status, whole-list labels and assignees, and comments (docs/github.md "Writes and claims"). Title and description edits and `+=`/`-=` are refused.

Add title and description updates through `updateIssue`. Implement `labels+=`/`labels-=` and `assignees+=`/`assignees-=` with GitHub's add and remove mutations, so a concurrent addition by someone else isn't overwritten the way a whole-list replace would. Each mutation runs after the existing composite-version preflight, is sent once, and reports `unknown-outcome` when the result is unknown. When label statuses are configured, a `labels` edit that changes the mapped labels recomputes status on read-back like any other edit.

## Summary

GitHub source now edits title (Set title) and description (ReplaceSection Description) via REST PATCH /issues/N, and supports labels+=/-= and assignees+=/-= via REST POST/DELETE /issues/N/labels|assignees, so concurrent additions survive. Add of a present or remove of an absent entry sends nothing. Every mutation runs after the composite-version preflight, is sent once, and reports unknown-outcome on any post-dispatch error (except local scheduler refusal) or failed read-back. Supporting changes: PrepareFields handles Description replacement and case-insensitive list add/remove inverses (TUI path); MCP update unwraps a single change like the CLI (GitHub has no batch); engine rejects += / -= on GitHub non-list-entry fields; TUI note key requires ReplaceSection+AppendNote.
