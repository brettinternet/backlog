## Why

Rank is the second key in Next's order (design.md §6), so it's how a person says "this before that" within a priority. format.md says `bl` generates fractional keys so a move rewrites one line, but nothing generates them: the only producer is the Backlog.md importer (`assignRanks`, internal/source/backlogmd/import.go:1104). Fifty items here carry imported keys. Every newer item is unranked and sorts after all of them, and reordering means hand-writing a key that sorts between two others.

## Design

- **Keys.** One function returns the shortest key strictly between two keys, either of which may be unset (an open end), compared bytewise, using only `0-9a-z` so keys stay plain YAML scalars. It accepts existing keys of any length, such as the importer's `a%016x` and hand-written `a3`, and never rewrites a neighbor. Creates stay unranked: ranking every new item would push unblock impact (§6 step 3) out of the order.
- **Moves.** `bl move ID... (--before X | --after X)` places the items, in argument order, contiguously beside X, writing only `rank`. Placing beside an unranked item first ranks the unranked items needed to keep the displayed order (from the first unranked item through X, after the source's greatest key), so nothing jumps further than asked. The whole move is one undoable edit. MCP `update` gains `operation: move` with `before` or `after`. Moves stay within one source; a target in another source refuses `rejected`.
- **TUI.** `alt+k`/`alt+up` and `alt+j`/`alt+down` move the selected item one row; `.` repeats. They work where the first sort key is `rank` or `next`. In `next`, priority outranks rank, so a move stops at a priority boundary and the status bar points to `p`. Elsewhere, including the tree, the keys are disabled with `sort by rank or next to reorder`. The item stays selected.
- **Sources.** Native only. Backlog.md stores an integer `ordinal`, and Linear (`sortOrder`), Jira (rank API), and GitHub Projects (item position) each order differently; until one is ported, moves there are disabled naming the source (D10).

## Tests

- Key generation over random and adversarial pairs (adjacent keys, `a` and `a0`, open ends, long keys): the result sorts strictly between. A wrong key silently reorders Next.
- A move beside an unranked item ranks only the run it needs and keeps every other item's relative order; undo restores every key written.
