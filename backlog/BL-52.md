## Why

Backlog.md 1.52 writes each criterion and definition-of-done entry as `- [ ] #1 text`, and renumbers the `#N` index whenever an entry is added or removed. The importer keeps `#1` as part of the text, and `bl` never renumbers it, so after an edit the text names the wrong number. That is the stale-number problem D28 removed. This repository's imported tasks carried these indexes until they were cleaned by hand.

## What

- During import, strip a leading `#N ` index from task-list entries in Acceptance criteria and Definition of done, alongside the HTML markers, keeping the text and checked state.
- Report the removal as a mapping decision, and make docs/import.md match.
- BL-36 reuses this decoder for reads and writes the index back.

## Acceptance criteria

- [ ] Importing a Backlog.md 1.52 task with indexed criteria and definition-of-done entries yields entries without `#N`, with text, order, and checked state unchanged, and `bl check` accepts the result
- [ ] An entry whose text starts with `#` after the index, such as `#1 #12 regression`, keeps `#12 regression`
- [ ] docs/import.md and the import report describe the removal

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change
