Every forge refresh, every minute while the TUI is open, reads mergeStateStatus, reviewDecision, and the statusCheckRollup for every open pull request in the repository. On cli/cli only a handful of its 61 open pull requests link to anyone's items, yet those fields are most of the cost. Median times through `gh api graphql` on 2026-11-17:

| Read | Time |
| --- | --- |
| Open page of 50, as now | 7.2 s |
| Open page of 50, without the three | 1.3 s |
| Those three, by number, for 5 pull requests (aliased `pullRequest(number:)`) | 1.3 s |

Outcome: the open pass reads the list without mergeStateStatus, reviewDecision, and the statusCheckRollup. Then one aliased query reads those three for the open pull requests linked to unfinished items, in chunks of at most 50, active items' pull requests first. An open pull request linked to no unfinished item carries no merge state, review, or checks. Its list glyph is empty, and `merge:`, `checks:`, and `review:` don't match through it. The linked set comes from the last link pass, both in the TUI's tracker and in one-shot loads (`bl changes`, MCP `changes`, `bl ls` and MCP `query` with a change term). A one-shot load links, reads the linked set, and links again. When a pull request becomes linked, the TUI shows its verdict after the next forge load, not the next minute tick. A github-pulls source's pull request items (D44) count as unfinished items, so configuring that source keeps today's reads.

Non-goals: GitLab (it keeps reading its fields), the detail read for the item shown (unchanged), closed and merged pull requests (an earlier task drops their review and checks).

## Summary

GitHub's list read no longer asks for mergeStateStatus, reviewDecision, or statusCheckRollup. After linking, Forge.Verdicts reads them in one aliased GraphQL query per 50 pull requests for open PRs linked to unfinished items (active first) plus every open PR of a github-pulls repository. One-shot loads link, read, and relink; the TUI projection hands the linked set to the tracker (SetLinked, O(1)), which reloads early when the set gains a PR.
