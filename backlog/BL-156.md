Phase 3a of BL-103. `enter` on a Changes entry opens the change view from BL-103's design: it replaces the detail pane, `backspace` returns, and its tabs start with Overview, Files, and Commits. BL-148 adds Diff, and BL-154 adds checks, reviewers, and Conversation. Branches and worktrees gain +/−, files, and commits from git on the detail worker, so a local change reads like a pull request. `!` keeps the actions menu. A pull request without a local head reads its files and commits from the forge through the account queue.

## Acceptance criteria

- [ ] `enter` on a Changes entry opens its change view in place of the detail pane with Overview, Files, and Commits tabs, `backspace` returns to the item, and `!` still lists the change's actions
- [ ] A branch or worktree change shows +/− against its merge base with the default branch, counting a worktree's uncommitted files, in its Changes entry, bl changes --json, and MCP changes
- [ ] Files lists each changed file with its status (added, modified, deleted, renamed, binary, or uncommitted) and +/−; Commits lists the change's commits newest first, from git for local heads and landed merges and from the forge for a pull request without a local head
- [ ] Git and forge reads run on the detail worker for the item shown, never on the update loop; git keeps D43's flags, skips uncommitted counts when repository config defines a filter driver, and the D43 row lists the added commands
- [ ] The Changes entry's second line shows a worktree path relative to the checkout root (or with ~), omits zero ahead and behind counts, and fits its facts at 80 columns
- [ ] Held `j` in a Files tab of 5,000 entries meets the §11 navigation budget

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change
