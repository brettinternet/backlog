Phase 3b of BL-103: the Diff tab in the change view (BL-156). Local stages diff with git on a worker, landed changes diff the merge against its first parent, and pull requests without a local head use the forge's per-file patches. BL-150's line comments and BL-151's tours anchor to diff lines, so address each by file, side, and line at a head SHA. See BL-103's change view design.

## Acceptance criteria

- [ ] The Diff tab shows the change's diff unified below 120 columns and split at 120 or wider, highlighted with chroma, with word-level intra-line changes

- [ ] `[`/`]` jump files, `[c`/`]c` jump hunks, and `/` searches the diff, as in detail

- [ ] A branch or worktree diffs against its merge base with the default branch plus a worktree's uncommitted changes, a landed change diffs its merge against the first parent, and a pull request without a local head uses the forge's per-file patches, saying when the forge truncated a file

- [ ] Git runs on a worker with --no-ext-diff --no-textconv, no pager, and D21's environment, and skips uncommitted changes when repository config defines a filter driver; a test asserts configured external diff, textconv, and filter commands never run

- [ ] Rendering is async and cached by head SHA, file, width, and theme; files over 32 KiB render on `m` up to 128 KiB, and held `j` over a 10,000-line diff meets the §11 budget

- [ ] `enter` on a History commit row opens that commit in the Diff tab

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change
