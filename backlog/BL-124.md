### Why

`bl comment`, MCP `append` with a comment, and the TUI `c` key require `me.default` (or `--author`) before any write, so commenting on a GitHub, Linear, or Jira item fails with "comment author is not configured" when only the source account is set up. The author never reaches those providers anyway: GitHub, Linear, and Jira all attribute a comment to the authenticated token's user (`internal/source/github/write.go`, `internal/source/linear/write.go`, `internal/source/jira/write.go`). A local author on a remote comment is either redundant or misleading.

### Shape

Resolve the comment author per target source with `cfg.Identities()` (`internal/project/identity.go`): the account user for GitHub, Linear, and Jira, `me.default` for native, Backlog.md, and external sources. Use it in the CLI (`internal/cli/write.go`), MCP (`internal/mcp/server.go`), and TUI, where the gate checks the selected item's source instead of one global `CommentAuthor`. An explicit author on a remote item is refused with `rejected`, naming the account user, because the provider can't attribute a comment to anyone else. Native and Backlog.md behavior is unchanged.
