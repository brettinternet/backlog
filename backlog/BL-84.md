People want to find the coding-agent session that worked an item. Worklease records the caller's session ID unchanged as each claim epoch's sessionId and keeps it in resource history after release (worklease WL-172, docs/claim-model.md). bl reads only active claims (worklease status/list in internal/worklease/coordinator.go), so once an item is released or done there is no way to see who worked it without knowing its Worklease resource key. Read retained epochs with worklease history --resource KEY --json for the item's coordination resource and show them on the item. Separately, bl instructions workflow says only to use a stable, distinct session; it should say to prefer the harness's own session ID (for example a loop-run ID, CLAUDE_CODE_SESSION_ID, or PI_SESSION_ID) so the recorded sessionId leads back to a transcript.
