Linear relation edits do not bump updatedAt, and deletions or moves out of scope cannot be seen by the minute change window, so they wait for the hourly reconciliation (docs/linear.md#sync). Meanwhile:

- bl next --claim ranks from the cached snapshot and claims without a fresh provider read (internal/engine/next.go), so an item that gained a blocker in Linear can be handed to an agent for up to an hour.
- TUI detail and bl show read the item fresh (engine.ReadItem), but the result never updates the snapshot, so the row and its detail can disagree.
- R calls Store.Refresh, which runs a normal Load; the Linear adapter only reconciles if the hour has elapsed, so a manual resync does not resync.

Applies to every remote source with the same gap; Linear is the motivating case.

## Acceptance criteria

- [ ] next --claim re-reads the selected remote candidate before acquiring and skips it if the fresh read makes it not ready (new open blocker, closed, archived, gone)
- [ ] Fresh provider reads from detail, show, and write preflight update the item in the store snapshot without blocking the update loop
- [ ] R forces a full reconciliation for remote sources; the minute poll keeps its current cost
- [ ] docs/linear.md, docs/tui.md, and docs/design.md describe the on-demand reconciliation
