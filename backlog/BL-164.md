A wrong tour can only be replaced by storing another, or abandoned by moving the head. Add a way to delete the stored tour for a change. Low priority until someone needs it.

## Acceptance criteria

- [x] bl tour ID --remove [CHANGE] deletes the stored tour for the item's linked change (or each, when unambiguous), and the MCP tool has the same option
  Evidence: bl tour ID --remove [CHANGE] (internal/cli/read.go) and MCP tour remove/change (internal/mcp/server.go) call engine.RemoveTour; refuses an unlinked CHANGE and several stored tours without CHANGE. go test ./internal/mcp (TestEventsMatchCLI: CLI remove, MCP remove with change branch:fix, reads back tours:[]) passed.
- [x] Removing when none is stored succeeds and says so
  Evidence: Removing with none stored returns removed:false (exit 0) and text 'No tour is stored for ...'; TestEventsMatchCLI asserts CLI and MCP give identical removed:false results. go test ./internal/mcp passed.
- [x] The TUI Diff tab shows no tour for that change on its next render
  Evidence: TUI reads the tour per Diff render via engine.LoadTour (no tour cache; file render key includes step ranges). TestChangeTour now asserts a removed tour shows no steps or notice on the next Diff render; mutation check (tour still stored) failed as expected. go test ./internal/tui passed.
- [x] docs/cli.md and docs/mcp.md describe removal
  Evidence: docs/cli.md (bl tour section) and docs/mcp.md (tool table and tour paragraph) describe removal; also internal/instructions/tours.md and design.md D43.
