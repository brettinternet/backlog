Item bodies, especially from GitHub Issues sources, use GitHub-only Markdown that Glamour renders poorly. An alert (`> [!WARNING]` followed by its text) renders as `| [!WARNING] Migration drops the old index.`: the marker runs into the text. A fenced block renders as indented code without its language, so a `mermaid` block reads as unexplained code.

Outcome: before Glamour renders a body, each alert (NOTE, TIP, IMPORTANT, WARNING, CAUTION) becomes a quote headed by its bold type name on its own line, and each fenced block with an info string shows its language as a dim caption above the block. Glamour exposes no goldmark extension hook, so this is a fence-aware rewrite of the body in `internal/tui/markdown.go`, reusing the fence rules in docs/format.md (`fenceState` in `internal/format/document.go`). Rendering stays async and cached (D14), and output still passes D21 sanitization.

Out of scope: rendering Mermaid (a follow-up item builds on the caption), math, footnotes, `<details>` (already readable), and linking `#N` or `@user`.

Modified files: internal/tui/markdown.go and its test, internal/format/document.go if the fence scanner is exported, docs/tui.md (Rendering).

## Summary

Before Glamour renders a body, markdown.go rewrites alert marker lines to a bold type name, tagged with an invisible mark. After rendering, it drops the blank quote line Glamour puts after the title. Unindented fences with an info string get a caption paragraph (dim unless NO_COLOR or high contrast). Lines inside fences are untouched (format.Fence, now exported). Verified with TestMarkdownAlertsAndFenceCaptions and task ci on main e092730.
