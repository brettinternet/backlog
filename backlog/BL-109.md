### Why

The Windows build reports claims as unavailable because Worklease doesn't support Windows. Once a Worklease release does, `bl` should coordinate on Windows exactly as it does on Unix.

### Shape

Remove the Windows `unavailable` guard and gate claims on the installed Worklease version, reported through `worklease version --json`, which `bl doctor` already probes. Run the coordination tests in the Windows CI job against that Worklease release.

## Acceptance criteria

- [ ] With a Windows-capable Worklease installed, bl next --claim --start from two sessions on Windows returns different items, and heartbeat, done, and release behave as on Unix
- [ ] With an older Worklease, claim commands still fail with the structured unavailable error, and bl doctor names the required version
- [ ] The Windows CI job runs the coordination tests against a Windows Worklease release
- [ ] The design.md register no longer excludes claims on Windows
