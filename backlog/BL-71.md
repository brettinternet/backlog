Package `bl serve` for hosts that run containers, following Worklease's [container deployment](https://github.com/brettinternet/worklease/blob/main/docs/container.md): the release binary in a minimal image, linux amd64 and arm64, immutable `vVERSION` tags and no `latest`, non-root UID/GID 65532, and no container-only behavior.

One writable volume holds the served checkout, which includes the write lock and ID counter in the Git common directory (D22), plus XDG state for events and trust. The cache is disposable and can live on tmpfs. Configuration and the token store mount read-only. A compose example runs `bl serve` next to `worklease serve`, so one host serves both data and claims.

## Draft until decided

1. **Base image.** `scratch` works for a native backend without `git.autoCommit`. Auto-commit needs `git` in the image, and a Beads backend needs `bd` 1.3.0.
   **Recommendation:** publish one image on a digest-pinned Alpine base with `git` and `ca-certificates` only. A `scratch` image without auto-commit would put the server's writes outside Git history, which drops native's main advantage over Beads (BL-70). Don't publish a Beads variant: multi-host Beads users are better served by Dolt server mode (BL-73), and anyone serving Beads through `bl serve` can `FROM` this image and add `bd`. docs/container.md shows that.
2. **Checkout provisioning.** Does `bl serve` clone the repository, or require an existing checkout?
   **Recommendation:** require an existing checkout and refuse to start without a project at the mounted path, naming it. Cloning needs Git credentials and fetching, which D9 keeps out of `bl`. The compose example clones once with a one-shot `git` container on the same volume, using the operator's own credentials.
3. **Git ownership and identity.** Auto-commit in the container needs a checkout Git trusts and a commit identity. Git refuses a repository owned by another user (`safe.directory`), and D9 only warns when a commit fails, so a misconfigured server would keep writing without history.
   **Recommendation:** the volume is owned by 65532, as Worklease's `install -d -o 65532` steps do, so neither `bl` nor the image sets `safe.directory`. The one-shot clone sets `user.name` and `user.email` in the checkout's own config. With auto-commit on, `bl serve` refuses to start when Git rejects the checkout or has no identity, naming the setting.

## Recommendation

Below the line, with BL-70. BL-72 is done, so BL-70 is its only open blocker.
