The MCP tour tool takes only a file path, which fails when the agent doesn't share bl's filesystem (a sandbox, a container, another machine). Accept the tour itself: an MCP argument holding the tour object, and bl tour ID - reading stdin. Both go through the same validator and limits as a file.

## Acceptance criteria

- [x] The MCP tour tool accepts a tour argument with the tour object instead of file; giving both or neither is refused with the reason
  Evidence: go test ./internal/mcp -run TestEventsMatchCLI PASS: MCP tour with a tour object stores (steps:1); file+tour refused 'give file or tour, not both'. Neither keeps the existing read-back mode (documented), since the tool without file already reads stored tours.
- [x] bl tour ID - reads the tour from stdin
  Evidence: TestEventsMatchCLI PASS: bl tour 1 - with stdin stores; direct run 'bl tour BL-162 - --json' with a bad ref exits 5 'tour ref must be the full head commit SHA'.
- [x] Inline tours pass the same validator, size limit, and refusals as files; a parity test covers CLI stdin and MCP inline
  Evidence: TestEventsMatchCLI PASS: one table drives CLI stdin and MCP inline through store, another ref, >1 MiB ('tour exceeds 1 MiB'), and a missing criterion, asserting the same refusal text; both go through engine.StoreTour/tour.Parse.
- [x] docs/mcp.md, docs/cli.md, and bl instructions tours show the inline form
  Evidence: docs/mcp.md (table + inline example), docs/cli.md (bl tour ID [FILE|-]), internal/instructions/tours.md (stdin and MCP inline forms), plus design.md D43 and schemas/tour.json description; task ci PASS.
