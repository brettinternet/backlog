bl tour, MCP tour, and the {"tour": PATH} result accept a step on a file or line the change lacks; the reviewer then sees "line N isn't in this diff" and the agent never learns. Storing resolves every step against the file at ref (or its parent for side old, and a renamed file's old path), off the TUI, with changes.FileAt, and refuses with every bad step listed so an agent can fix them all in one pass. Builds on BL-151.

## Acceptance criteria

- [ ] Storing a tour refuses a step whose file doesn't exist at ref (or before the change for side old) or whose line is past the file's end, naming each bad step's index, file, line, and the file's line count
- [ ] All bad steps are reported in one refusal, in the human and --json outputs and the MCP error
- [ ] Steps on files the change doesn't touch but that exist at ref are accepted, since the Diff shows them with context
- [ ] The check reads git objects at ref only, never the worktree, and stays within D14 (no work on the update loop)
- [ ] bl instructions tours and docs/cli.md describe the check

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change
