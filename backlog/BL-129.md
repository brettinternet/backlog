Today a GitHub source is bound to one repo: listQuery pages the repo issues and joins Projects v2 status, and issues not in the project are `unknown`. Make `repo` optional when `githubProject` is set. A project-only source reads every item in the project, driven by the project items query with issue fields on each item, so issues from any linked repo appear under their own owner/repo#N ref and claim key. Repo-only sources keep current behavior. With both set, `repo` is the default target for creates and draft conversion (BL-128). Risks to settle first: incremental sync must rely on project item updatedAt, so probe live whether an issue edit (title, body, labels, assignees, state, comments) bumps the project item updatedAt; if not, design a bounded fallback that keeps D14 and the §11 budgets. Items from repos the credential cannot read return null content; App installations and permission rechecks are per repo. Changes the D24/D34/D35 source identity, so it needs a decision register entry.
