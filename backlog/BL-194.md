Found closing BL-175 (2026-11-17). On cli/cli, `bl changes ID --detail` reports `github cli/cli unavailable: remote HTTP: provider refused request`, so no pull request in that repository shows. The first refresh pages every pull request in all states, 50 per page, up to changes.MaxPulls (1000). Each page of pullsQuery takes 4-11 s on cli/cli, and one page returns 502 Bad Gateway with or without mergeStateStatus (probed with gh api graphql and the exact query and variables). One failed page fails the whole refresh and caches nothing, so it never converges.

mergeStateStatus roughly doubles page time and only means something for open pull requests, yet the all-states pass reads it too.

Options to weigh: keep pages already read and resume from the cursor on the next refresh; a smaller page size, or halving it after a 502; read mergeStateStatus only in the open pass.

## Acceptance criteria

- [ ] A first refresh on a repository with over 1000 pull requests, where a page returns 502, still lists the open pull requests and converges on later refreshes
- [ ] The all-states pass doesn't read mergeStateStatus, and merge: and the list verdict glyph are unchanged
