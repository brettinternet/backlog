D19 says MCP tools mirror the CLI operations, but `bl events` has no MCP counterpart. An agent on MCP cannot ask what changed since it last looked, see whether its action's chained hooks succeeded (`hook.finished` outcome), or notice readiness changes, without shelling out.

Add a non-follow `events` tool: `since` and `query` with the CLI's semantics (event terms `changed:`, `hook:`, `action:`, `outcome:` enabled), plus a `limit` and the last returned ID so a caller pages forward with `since`. No follow or streaming; MCP callers poll. Reuse the CLI's reader and filter so the shapes cannot diverge.

## Acceptance criteria

- [ ] MCP exposes an events tool taking optional since (exclusive ULID) and query, returning the same data.events shape as bl events --json
- [ ] An unknown since ID returns the same not-found style error as the CLI; results are bounded (limit with a documented default and a cursor to continue)
- [ ] docs/mcp.md and design.md §7 list the tool
