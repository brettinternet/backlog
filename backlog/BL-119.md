GitHub writes cover status, whole-list labels and assignees, and comments (docs/github.md "Writes and claims"). Title and description edits and `+=`/`-=` are refused.

Add title and description updates through `updateIssue`. Implement `labels+=`/`labels-=` and `assignees+=`/`assignees-=` with GitHub's add and remove mutations, so a concurrent addition by someone else isn't overwritten the way a whole-list replace would. Each mutation runs after the existing composite-version preflight, is sent once, and reports `unknown-outcome` when the result is unknown. When label statuses are configured, a `labels` edit that changes the mapped labels recomputes status on read-back like any other edit.

## Acceptance criteria

- [ ] Title and description edits from the CLI, TUI, and MCP update the issue after the version preflight
- [ ] labels+=, labels-=, assignees+=, and assignees-= use add and remove mutations, so concurrent additions survive
- [ ] Each mutation is sent once and reports unknown-outcome when the result is unknown
- [ ] A live test covers each write; docs/github.md writes section is updated

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change
