## Why

Agents here report progress by checking criteria with evidence, but a row shows only child progress (`▣ a/b`). In the Active tab you can't tell an item at 1/12 from one at 11/12 without opening each.

## Scope

- A `criteria` column shows checked and total acceptance criteria (not DoD, matching `has:criteria`), such as `☑ 3/5`, blank when there are none. Views accept it in `columns` (internal/project/config.go:674).
- The built-in Active tab shows it by default; other built-in tabs don't, to keep their rows narrow.
- As the pane narrows, it drops together with children and change (docs/tui.md Layout).
- Counts are computed while rows are prepared on the projection worker, never in Update or View (D14).

## Acceptance criteria

- [ ] A criteria view column shows checked/total acceptance criteria per row, blank without criteria, and views.columns accepts it
- [ ] The built-in Active tab shows the column by default, and it drops with children and change as the pane narrows
- [ ] Counts are computed on the projection worker, not in Update or View
- [ ] docs/tui.md describes the column

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change
