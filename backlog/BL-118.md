GitHub sources refuse create, so `bl new`, TUI create, and MCP `create` are unavailable. Follow the Linear create work (BL-112, BL-113, BL-114): declare Create in capabilities, gated by writes, and implement it in Apply. Skip the version preflight, send one non-retried `createIssue` with title, body, labels, and assignees (plus the status label when label statuses are configured), then read the new issue back.

Each follow-up is sent once after the issue exists: `^` parent through `addSubIssue`, `<` blockers through `addBlockedBy`, and with a bound project, `addProjectV2ItemById` plus the status option. If a follow-up or the read-back fails, return `unknown-outcome` carrying the created ref, and record no undo (design.md D15). Reject fields GitHub can't store (milestone by key, type, priority, criteria, sprint) before dispatch.

Undo of a clean create uses `deleteIssue` when the viewer can delete it (repository admin, deletion not disabled by the organization, and allowed for the credential, including the `bl-cli` App token) and the issue is still at the version create returned. Otherwise it closes the issue as not planned. The undo result says which happened. Redo isn't offered after a delete, because recreating would assign a new number. Deletion can't withdraw notifications or webhooks already sent. Record this in D15.

## Acceptance criteria

- [ ] bl new --source issues creates an issue with title, body, labels, assignees, and its label status, then reads it back
- [ ] Parent and blockers become a sub-issue and blockedBy relations, each sent once; a failed follow-up returns unknown-outcome naming the created issue and records no undo
- [ ] With a bound project, a create status adds the issue to the project and sets the option under the same follow-up rules
- [ ] A network failure after dispatch reports unknown-outcome without retry; unsupported fields are rejected before dispatch
- [ ] TUI create is offered when writes are allowed; undo deletes the new issue when permitted and unchanged, else closes it as not planned, reports which, and offers no redo after a delete
- [ ] A live test creates and closes an issue in the test repo; docs/github.md and design.md D15 are updated
