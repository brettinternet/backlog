### Why

`bl` ships only for macOS and Linux. Windows users and agents running on Windows hosts can't use it. Go cross-compiles easily, but `GOOS=windows go build ./...` fails today, and several paths would compile and still misbehave.

### Findings

- **Doesn't compile:** `syscall.Flock` in `internal/autocommit/autocommit.go` and `internal/project/views.go`, `unix.Flock` in `internal/hooks/events.go`, `Setsid` in `internal/hooks/runner.go`, and no Windows `FileIdentity` in `internal/cache`.
- **Compiles, behaves wrong:** `$EDITOR` runs through `/bin/sh` (`internal/cli/write.go`, `internal/tui/long_edit.go`). The OAuth store checks `Perm()&0o077`, which every Windows file fails. Renaming over a file that another process holds open returns access denied, which breaks D8 atomic writes. `watch_other.go` falls back to 50 ms polling, which breaks the §11 idle budget. `process_other.go` kills only the direct child.
- **Worklease doesn't support Windows** (its go-rewrite contract D3) and doesn't compile for it. Claims are optional (§2), so `bl` can ship on Windows without claims first.
- Already fine: filenames are `<id>.md`, the format accepts CRLF and preserves line endings, URL opening has a Windows branch, and Bubble Tea v2 supports the Windows console.

### Plan

1. Build and run `bl` on Windows without claims, with a Windows CI job.
2. A native `ReadDirectoryChangesW` watcher that meets the §11 budgets.
3. Windows release archives and a PowerShell installer.
4. Port Worklease to Windows (other repository, owner).
5. Enable claims on Windows.

Record the supported platforms as a new decision in the design.md register during step 1.
