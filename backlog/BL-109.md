### Why

The Windows build reports claims as unavailable because Worklease doesn't support Windows. Once a Worklease release does, `bl` should coordinate on Windows exactly as it does on Unix.

### Shape

Remove the Windows `unavailable` guard and gate claims on the installed Worklease version, reported through `worklease version --json`, which `bl doctor` already probes. Run the coordination tests in the Windows CI job against that Worklease release.

## Acceptance criteria

- [x] With a Windows-capable Worklease installed, bl next --claim --start from two sessions on Windows returns different items, and heartbeat, done, and release behave as on Unix
  Evidence: CI run 40994005797 (9be3041, main) windows-latest 'Coordination tests' step: BL_PROVIDER_TESTS=1 go test -run Provider ./internal/cli ./internal/worklease against mise-installed Worklease 1.13.0 -> ok internal/cli 7.97s, ok internal/worklease. Covers TestProviderNextClaimConcurrentCLIAndMCP (two sessions get different items, done releases), TestProviderClaimRoundTripAcrossWorktree (start/heartbeat/done/release), TestProviderRunManagedWorker. Same tests pass locally on macOS.
- [x] With an older Worklease, claim commands still fail with the structured unavailable error, and bl doctor names the required version
  Evidence: TestOldWorkleaseNamesMinimumVersion (test binary as Worklease 1.10.0): doctor worklease check fails with Fix naming MinimumVersion on all platforms; on Windows claim/start/next --claim --start refuse 'unavailable' naming 1.13.0 and leave the item unchanged. Passed in CI run 40994005797 (9be3041, main) windows-latest Tests step (ok internal/cli 61.7s) and locally.
- [x] The Windows CI job runs the coordination tests against a Windows Worklease release
  Evidence: .github/workflows/ci.yaml Windows job installs github:brettinternet/worklease (mise pin 1.13.0, windows-x64 release asset) and runs the Coordination tests step; succeeded in CI run 40994005797 (9be3041, main) (rerun of a failed attempt whose only failure was the pre-existing flaky internal/source/native TestWatchedCacheRefresh).
