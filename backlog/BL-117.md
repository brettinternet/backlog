Most GitHub repositories use plain issues without Projects v2. Today every open issue is todo, so it is ready, which is unusable alongside agent loops. Let a source map issue labels to statuses, mirroring `githubProject.options`:

```yaml
sources:
  - id: issues
    type: github
    repo: acme/app
    account: personal
    statusLabels:
      ready: todo
      in-progress: active
statuses:
  - {key: unknown, name: Triage, category: backlog}
  - {key: closed, name: Closed, category: done}
  - {key: ready, name: Ready, category: todo}
  - {key: in-progress, name: In Progress, category: active}
workflow: {start: in-progress, done: closed}
```

Reads, when `statusLabels` is set. Untriaged issues use `unknown`, the key Projects mode already uses for an unmapped option, so every GitHub key keeps one category (BL-116):

| Issue | Status | Category |
| --- | --- | --- |
| Closed | `closed` | done, or canceled for not planned, whatever its labels |
| Open, exactly one mapped label | the label key | the mapped category |
| Open, no mapped label | `unknown` | backlog (never ready) |
| Open, several mapped labels | `unknown` | backlog, with a finding naming the labels (fail closed) |

Label names match case-insensitively, as GitHub does. Mapped labels also stay in `labels`.

Writes: `status=LABEL` on an open issue replaces the mapped labels with that one in a single label write, keeping other labels, after the usual version preflight. `status=unknown` removes the mapped labels. `status=closed` closes as completed, and `status=open` reopens, as today. A label status on a closed issue is refused (reopen first), so each write stays one mutation. `workflow.start` may be a mapped label, so `bl next --claim --start` works on plain issues.

Config errors: `statusLabels` together with `githubProject`, an invalid category value, a duplicate label, or a label named `open`, `closed`, or `unknown`. BL-116's validation covers mapped labels.

Update docs/github.md (a "Label statuses" section before Project status), docs/guide.md config, and add a design.md decision.
