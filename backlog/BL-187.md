## Why

Inside a worktree, people and agents know the branch (`bl-140-slug`), not the ID, and the branch already names the item under D43's linking rule. Every command still needs the ID typed out.

## Scope

- `.` is accepted wherever the CLI takes an item ID. It resolves the invoking checkout's current branch (DIR's with `-C DIR`; never the control root's, D5), read without starting Git (`Discovery.Branch`, internal/project/discovery.go:325), through the branch rule changes already use (`branchIDs`, internal/changes/link.go:196), shared rather than copied.
- A detached HEAD or a branch naming no item exits 3 naming the branch. A branch naming several items exits 2 listing them, as an ambiguous ID does.
- MCP refuses `.` with `usage`: the server's checkout isn't the caller's (design.md §7).
- The TUI, started in a checkout whose branch names exactly one item, opens that item's detail as go-to does. The primary checkout on the default branch names none, so its startup doesn't change.

## Docs and register

Amend D19's ID shorthand. Update docs/cli.md (IDs) and docs/tui.md (Startup).
