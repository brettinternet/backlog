Follow-up to BL-88. A `sprint:` term with no Linear or Jira source fails with "no source provides sprints" (internal/query/eval.go), but two paths skip that check. `ready.sprint` in a native-only project makes every item ineligible with reason `sprint` and gives no warning (internal/engine/readiness.go). `group:sprint` is accepted and puts everything in `none` (internal/query/projection.go). In a workspace, the check is per project.

## Acceptance criteria

- [ ] ready.sprint with no Linear or Jira source in the project fails config validation with "no source provides sprints" (bl check / bl config show)
- [ ] group:sprint with no capable source is a validation error in the CLI and a warning in the TUI, as sprint: terms are
- [ ] Projects with a capable source behave as before; docs (format.md or design.md D31, query.md) state the rule

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change
