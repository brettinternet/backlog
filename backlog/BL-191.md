## Why

`due` is in the native format (`YYYY-MM-DD`), the query language (`due:<today`), sort (`o d`), and `bl set due=`, but nothing sets it interactively: no picker, no quick-add token, no column, and no overdue marker.

## Sketch

- A due picker taking `YYYY-MM-DD`, `today`, `tomorrow`, a weekday (its next occurrence), `+3d` or `+2w`, or `none`, showing the resolved date before saving. `bl set due=` accepts the same words and stores the date.
- A quick-add token for due.
- A `due` view column with an overdue glyph, since color is never the only signal.
- One date parser shared with BL-172's start date.

## Open questions

1. Key and quick-add sigil: `w` is sprint, and `!@#^<~:+` are taken.
2. Provider mapping: Linear `dueDate`, Jira `duedate`, and GitHub Projects date fields, or native only first?

## Recommendation

Below the line: no item in this repository has a due date. Promote when a project using `bl` needs them, or alongside BL-172.
