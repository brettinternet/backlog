## Why

Claim history records a session string and the login user (`agent: "brett"`), but not which agent ran it or where. Without the agent kind, host, and checkout, nothing can resume the session or explain it later. This is the foundation for handoffs, resume, and the History tab (see the parent epic for principles: local, decaying, resilient).

## Shape

**Register.** Add D40 "Item history" to design.md: session identity is recorded on local events. Handoffs are local unless `history.handoff: comment`. Resume and fork commands come from built-in and user `agents:` config only. The timeline is composed from independent sources that degrade one at a time. Nothing is written to item files or required for correctness. Add a §2 non-goal: storing or reading agent transcripts.

**Event field.** Events produced by a `bl` command run with a caller session (`--session`, `BL_SESSION`, `WORKLEASE_SESSION_ID`, or the MCP `session` argument) gain an optional `session` object. This covers `item.*` from writes, `claim.acquired`, `claim.released`, and `action.finished`:

```json
"session":{"id":"71e98dd4-…","agent":"claude","agentSession":"71e98dd4-…","host":"brett-mbp","cwd":"/Users/brett/dev/me/backlog/.worktrees/bl-140-…","branch":"bl-140-…"}
```

- `id`: the caller session. `agent`: the detected kind, or omitted. `agentSession`: the harness's own session ID, defaulting to `id`. `host`: `os.Hostname()`. `cwd`: top level of the checkout `bl` ran in, not the control root. `branch`: that checkout's branch, read from `.git` without spawning Git (D5).
- This is additive within `schemaVersion: 1`. `origin: sync` events and the TUI's per-item `tui:` sessions (D39) carry no `session` object, or only `id`. TUI sessions aren't agent sessions and must never look resumable.
- Values go through D21's checks (no control characters, no leading `-`, ≤ 1 KiB) before they're recorded. A value that fails is dropped from the object and doesn't fail the command.
- Recording never blocks or fails a write. It rides on the event the write already appends (design.md §8, mutation step 5).

**Agent detection.** A new `agents:` config map, keyed by kind. This item adds only the detection key. BL-138 adds `resume` and `fork` to the same entries.

```yaml
agents:
  claude: {session: CLAUDE_CODE_SESSION_ID}   # env var whose presence detects the agent and supplies agentSession
  pi:     {session: PI_SESSION_ID}
  codex:  {session: CODEX_THREAD_ID}          # verify the real variable against the installed codex before shipping; omit if none
```

- Built-ins ship `claude` and `pi`, plus `codex` if verified. User config and user per-project overrides merge by key (D16). The project and local repository layers can't set `agents:`: `bl doctor` reports the key as ignored there, because BL-138 adds commands to these entries.
- CLI: `BL_AGENT=KIND` wins. Otherwise the first configured agent, in sorted key order, whose `session` variable is set and non-empty wins. Otherwise no agent.
- MCP never reads the caller from server environment (design.md §7). Write and claim tools accept an optional `agent` (kind) and `agentSession` beside `session`. Without them, `agent` is omitted and `agentSession` defaults to `session`.
- Update `bl instructions workflow` to tell MCP callers to pass `agent`, and keep telling everyone to use the harness session ID as the session.

**Read side.** `bl show ID` (CLI and MCP) gains `sessions`. It folds the item's events (by `session.id`) with claim history (joined by session ID), one entry per session: `id, agent, agentSession, host, cwd, branch, firstSeen, lastSeen, phases` (the item status categories seen across the session's events), `claim` (the claim epoch if any), and `ended` (`done`, `released`, `lapsed`, or open). A claim-only session from another host or an older `bl` has only the claim fields. Text output replaces the `## Claims` block with `## Sessions`, one line each.

- Reading every rotated event log per `show` would break the `bl show` ≤ 30 ms budget (§11). Index events by item ref in the cache (D23): a table rebuilt from the log when it's missing or behind, and appended incrementally like other cache state. The cache stays disposable. A cold rebuild may exceed the budget once, and it must not run on the TUI update loop (D14).
- A failed event read or index rebuild is reported beside the item, the same as a claim-history failure is today, never as a `show` failure.

**Docs.** Update events.md (the `session` field), design.md (D40, §8 events, §9 claim history to sessions), cli.md (`show` sessions, `BL_AGENT`), mcp.md (`agent`, `agentSession`), the user-config schema (`docs/schemas/user-config.json`), and the workflow instructions.

## Acceptance criteria

- [ ] design.md registers D40 (item history) with the §2 non-goal on agent transcripts, and events.md documents the optional session object
- [ ] A bl write or claim run under CLAUDE_CODE_SESSION_ID (or BL_AGENT) records session.agent, agentSession, host, cwd (the invoking checkout, not the control root), and branch on its event, without spawning git
- [ ] MCP write and claim tools accept agent and agentSession and never read them from server environment; TUI tui: sessions and sync events never carry an agent
- [ ] agents: config is honored from built-ins and user config and ignored with a doctor warning in project and local repository layers

- [ ] Warm bl show stays within the 30 ms budget on the 10k fixture with at least 100k events, via a per-item event index in the disposable cache
