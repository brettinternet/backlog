Move shared project configuration from .config/backlog.yaml to root-level backlog.yaml for discoverability, and add an optional gitignored .backlog.yaml private override layer. Preserve user-config projects overrides. Do not add .git/backlog.yaml: linked worktrees use a .git file and Git-local storage introduces unnecessary routing ambiguity. Keep the old shared path as a migration fallback and reject simultaneous legacy and new shared configs rather than silently merging them. Define private-layer precedence and primary-versus-checkout routing explicitly, preserving D5 control-root behavior and D16 trust protections. Hidden files are not inherently private; ensure private overrides are ignored, excluded from bl auto-commits, and are not a credential store. Update the decision register and native-format contract as part of implementation.

## Acceptance criteria

- [ ] Root-level backlog.yaml is discovered and loaded as shared project config; legacy .config/backlog.yaml remains a fallback, and coexistence produces an actionable ambiguity error.
- [ ] Optional .backlog.yaml overrides shared settings with documented precedence relative to user per-project overrides, environment, and flags; existing merge and provenance semantics remain intact.
- [ ] Primary checkout and linked-worktree behavior is defined and verified for both shared and private config, including root: checkout and repositories with only private configuration.
- [ ] Private config is gitignored and excluded from bl auto-commits; private-layer privileged entries preserve explicit trust requirements, and credentials remain user-only.
- [ ] Config discovery, initialization, migration guidance, config show, trust, schemas, README and matching specs consistently reflect the new paths and layering; D16 and any affected decisions are updated.
- [ ] Focused regression tests cover ambiguous shared paths, private override precedence, worktree routing and trust boundaries; task ci passes.
