Phase 4 of BL-103: a GitLab forge for merge requests through the same internal/changes forge interface as GitHub. bl has no GitLab source, so this adds a GitLab account (gitlab.com or a self-managed host, with a read_api token from `credential` or `env`, as Linear's API key) that only the forge uses. See BL-103 and docs/changes.md.

## Acceptance criteria

- [ ] A `type: gitlab` forge with a GitLab account fetches merge requests through the account's request queue into a per-project cache with an updated cursor, and a failed refresh keeps the cached merge requests marked stale

- [ ] A merge request links by source branch, whole-word ID in the title, or a closing pattern in the description, and shows state (draft, open, merged, or closed), pipeline status as checks, approval as review, and +/−

- [ ] A GitLab `origin` with exactly one GitLab account for its host is the forge without configuration, as for GitHub

- [ ] change:, checks:, and review: match linked merge requests, and bl changes --json and MCP changes report them with the GitLab forge in providers

- [ ] The token never reaches the cache, events, or logs, and tests use a fake server unless BL_PROVIDER_TESTS=1

- [ ] docs/changes.md, a GitLab setup page, and the D43 row describe the GitLab forge, its account, and its token scope
