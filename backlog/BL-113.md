BL-112 adds Linear Create but rejects parent and blocked_by. Support them: parent via issueCreate parentId (resolve the parent ref to a same-org Linear issue UUID; refuse cross-source refs), blocked_by via issueRelationCreate(type blocks, issueId=blocker, relatedIssueId=new) after the create. Relation creation is a second mutation after an already-applied create, so a failure must report the created item and the unapplied relations as a partial outcome, never retry the create, and never leave undo archiving a different issue. Also decide whether bl set parent/blocked_by on existing Linear issues comes along (issueUpdate parentId, issueRelationCreate/Delete) or stays separate. Update docs/linear.md and the design.md §10 Linear row in the same commit.

- [ ] Create with blockers creates each blocks relation once after the issue, never retries, and reports partial failure with the created item

## Notes

Scope caveat from BL-112: remote.Source.safeError (internal/source/remote/source.go) rewrites every source refusal to 'remote source refused operation', so a message carrying the created issue identifier never reaches the user (BL-112 already loses it when the post-create read-back fails). Reporting partial failure with the created item needs a structured channel past the wrapper (e.g. a typed partial-outcome error carrying the item Ref that safeError preserves); fix the read-back case with it.
