Move shared project config from `.config/backlog.yaml` to root `backlog.yaml` for discoverability, and add an optional private `backlog.local.yaml` override layer. `bl` is unreleased, so this is a hard cutover: no legacy fallback and no coexistence rules. A project that still has `.config/backlog.yaml` fails discovery with an error that names `git mv .config/backlog.yaml backlog.yaml`.

Decisions (record in design.md D5/D16 and §5):

- **Layers.** built-in < user < project (`backlog.yaml`) < local (`backlog.local.yaml`) < user-project (`projects.<id>`) < environment < flags. Repo files settle `project.id` before the user `projects.<id>` lookup, so identity resolves in one pass.
- **Routing.** Both files load from the control root, so every worktree sees one effective config (D5). `root:` is read from the control root's and the invoking checkout's shared and local files, with the invoking checkout's local file last. `root: checkout` loads both files from the invoking checkout.
- **Discovery.** Either file marks a `bl` project, so a repository you cannot commit to works with only `backlog.local.yaml`.
- **Trust.** The local file is a repo-file layer. Its hooks, actions, network sources, and `git.autoCommit` stay inert until `bl trust` and are part of the trust digest. The repository author controls `.gitignore` and can commit this file, so it gets no extra trust. Today `privileged()` treats any layer other than `project` as trusted and `trust.go` only digests the `project` layer. Replace both with one predicate naming the untrusted repo layers.
- **Schema.** The local file uses the project schema. It is not a credential store; accounts stay in user config.
- **Git.** `bl` never writes `backlog.local.yaml`, so auto-commit cannot include it. `bl` does not edit `.gitignore`; `bl doctor` warns when the local file is tracked or not ignored (doctor already runs `git`).
- **Not `.git/backlog.yaml`.** Linked worktrees have a `.git` file, and Git-local storage adds routing ambiguity.

- [ ] `backlog.local.yaml` overlays project config after `backlog.yaml` and before user `projects.<id>` overrides, with existing mapping-merge and list-replace semantics, and `bl config show` attributes its values to layer `local` with file and line.

## Plan

1. `internal/project`: add `ProjectFile`/`LocalFile` path helpers and use them in discovery, `detectSources`, `Resolve`, identity errors, and Backlog.md warnings. Fail discovery when `.config/backlog.yaml` exists.
2. `Resolve`: read the local file beside the selected project file (control root, or checkout under `root: checkout`), include it in `root:` resolution, and overlay it as layer `local` before the user-project lookup.
3. Trust: one `untrustedLayer(layer)` predicate (project, local) used by `privileged()` and the digest in `trust.go`.
4. Callers: `bl init`, `bl import` (config path and milestone reports), the doctor fix text and a tracked/not-ignored warning, the TUI banner, fixtures, and the doctest demo.
5. Move `.config/backlog.yaml` to `backlog.yaml` in this repo; add `/backlog.local.yaml` to `.gitignore`.
6. Docs: design.md D5/D16/§5, format.md layout, cli.md, guide.md, github/linear/jira/backlog-md/import docs, README, schema descriptions.
7. Tests named in the criteria, then `task ci`.
