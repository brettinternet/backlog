Found while writing `examples/` (3b93447). Each one is a gap between the docs and what `bl` does.

1. **Beads label-only writes fail.** `bl set app-2 labels=auth` exits with "bd command failed". `internal/source/beads/beads.go:346` always adds `--if-status`/`--if-assignee`, and `bd` 1.3.0 rejects those guards when the only change is labels. docs/beads.md says label edits are supported. Repro: `bd init`, `bd create`, then `bl set ID labels=x` in a project with a `type: beads` source.
2. **Native items can't reference provider items.** `blocked_by: [issues:128]` or `[jira:10001]` in a native file fails to load with "invalid-value: blocked_by reference" (`internal/format/document.go:190`), because every reference ID must match the native `PREFIX-N` grammar. docs/format.md says `source:ID` names another source in the same project, and Linear's `eng:ENG-431` happens to work. Validate unqualified refs against the native grammar, and accept a qualified ref when its ID is valid for the source it names. Unloaded or missing targets stay `unknown`.
3. **Unqualified quick-add blockers in multi-source projects are always local.** In a project with sources `web` and `api`, `bl new 'X <API-2' --source web` stores `API-2`, which means `web:API-2`. It doesn't exist, so the blocker is unknown and the item is never ready. No warning is shown. `ResolveRef` (`internal/cli/write.go:500`) treats unqualified refs as local, but design.md's ID shorthand resolves across configured native sources and cli.md says `<` stores "the target's real ID". When the local source has no match and exactly one other source does, store the qualified ref. Otherwise keep the local ref and warn on create, like `bl check`'s dangling-ref warning.
4. **docs/import.md contradicts readiness.** Line 80 says `ready.statuses` holds "the generated To Do-category keys", but `internal/engine/readiness.go` treats `ready.statuses` and `satisfiedBy` as status categories (`todo`, `active`, …). Check what import generates and correct whichever is wrong.

Once fixed, remove the workaround note in `examples/13-monorepo/README.md` (the paragraph on unqualified `<API-1`). Consider adding a native-plus-GitHub blocker to the examples.
