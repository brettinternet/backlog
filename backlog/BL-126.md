### Why

The TUI status picker, `<`/`>` status steps, and board moves use the project-wide `statuses` list. With the `issues` source configured, `>` on an issue in Triage (`unknown`) picks `todo`, which GitHub rejects, and a native task can be moved to `unknown`, `ready`, or `closed`, statuses that exist only for GitHub. Board columns mix both vocabularies.

### Shape

Offer each item only the statuses its source accepts, using the per-source status set introduced by the workflow item this depends on. Steps skip statuses the source doesn't accept, the picker lists only accepted ones, and a board move into a column the item's source can't take is disabled with a reason. Native writes of another source's provider-only status (`unknown`, `closed`, a label or option key) are refused when that status isn't one the native source owns.
