### Why

Every TUI shares one `tui` session (D39), and a Worklease session holds one claim, so a person can't claim a second item: `claim-held: session already holds …`. People multitask; agents run one loop per session.

### Shape

- Without an explicit session, the TUI coordinates each item under its own session, `tui:` plus a hash of the item's claim resource. The name derives from the resource, so reopening anywhere resumes every claim and replays a pending acquire, every source of an item (D37) and a key change (D20) find the same claim, and it fits Worklease's 128-byte session limit.
- An explicit `--session`, `BL_SESSION`, or `WORKLEASE_SESSION_ID` keeps one session for everything, as before.
- An item's claim is `mine` when its session is the one derived from that item's resource. Agents keep their own sessions and still see your claims as others'.
- `S`/`D`, status transitions, and renewal use the item's session. The TUI renews every claim it holds, off the update loop, at half the earliest remaining lease.
- D39, docs/tui.md, and docs/cli.md describe it.
