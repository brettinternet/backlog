Follow-up to BL-88, which added the Sprint model for Linear cycles and Jira sprints and named GitHub Projects v2 iteration fields as out of scope. An iteration has an ID, title, startDate and duration. Map the configured iteration field into the same catalog (current = the iteration containing today per the provider, next = the earliest future one, completed iterations as closed) so sprint:, ready.sprint and group:sprint work for GitHub project sources. Reuse the BL-88 catalog flow: one bounded request per sync, no catalog I/O on the update loop (D14).

## Acceptance criteria

- [ ] GitHub project sources with an iteration field publish a sprint catalog and per-item sprint; sprint:current|next|<name>, ready.sprint and group:sprint work as for Linear and Jira
- [ ] The iteration field is discovered from the project fields, not hardcoded; projects without one are not sprint-capable
- [ ] Catalog refresh adds at most one bounded request per sync; httptest fakes cover active, upcoming and completed iterations
- [ ] design.md D31, github.md and query.md document iteration support
