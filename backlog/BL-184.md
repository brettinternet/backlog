## Why

On 2026-11-17 one session created BL-174 and, 72 seconds later, BL-175: the same epic, title, and body. BL-175 got the children and the commit. BL-174 stayed an uncommitted file that ranked second in Next, because it has no children while the real epic is an ineligible container, so the next `bl next --claim` would have handed an agent the stray copy. Agents re-create when an outcome looks uncertain or a body needs rewriting, and `bl` accepts a second identical title without a word.

## Scope

- One engine check, shared by `bl new`, MCP `create`, and TUI quick-add and the full form (as D33 shares the create target), runs after the target source resolves and before dispatch. An open (backlog, todo, or active category), unarchived item in the target source with the same normalized title refuses the create with `rejected`, listing each match in the message and `error.details.matches`, as ambiguous IDs do.
- Normalized means Unicode case-folded, trimmed, and inner whitespace collapsed. Nothing fuzzier: a near match is a judgment call, and a false refusal costs more than a missed duplicate.
- `bl new --force` and MCP `create` `force: true` create anyway. In the TUI, saving shows the match in the status bar and creates only on a second `enter`; `esc` keeps the prompt.
- Closed, canceled, and archived items never match, so re-filing finished work is free. In a workspace, only the target source is compared.
- Remote sources compare against cached rows and never make a request. A stale or partial cache can miss a match; the docs say so.
- `bl check` warns `duplicate-title` (exit status unchanged) for open native items sharing a normalized title, so existing copies like BL-174 surface.
- Titles come from the native read cache, not a parse of every file.

## Docs and register

Amend D33 with the check. Update docs/cli.md (`bl new`, `bl check`), docs/mcp.md, docs/tui.md (quick-add), and `bl instructions workflow`: on `rejected` with matches, update the match instead of forcing.

## Tests

- Engine: a title differing only in case and spacing is refused in the target source with its matches listed; a closed, archived, or other-source match isn't. Catches the BL-174 case and an over-eager check that blocks re-filing finished work.
- `--force` creates.
