Linear assignees render as user UUIDs (internal/source/linear/linear.go:439 maps assignee{id} only), so the TUI board, detail, overlay, and CLI text show a GUID instead of a person.

Keep the stable ID as the stored value (writes, queries, @me, claims, undo all depend on it); add a display name alongside it and render that wherever the value is shown.

Same gap elsewhere:
- Jira assignees are accountId (internal/source/jira/jira.go:331); displayName is available on the same field.
- Linear status is the state UUID. The TUI falls back to the raw key (internal/tui/render.go:73) unless every state is hand-mapped in backlog.yaml statuses, although stateName is already read into item fields.
- GitHub Projects v2 status is the option ID (internal/source/github/github.go:423), same raw fallback.
- Pickers and completion for assignees/status offer raw IDs, so selecting a value requires knowing the UUID (docs/linear.md documents assignees=VIEWER_UUID).

Not affected: GitHub assignees (login), Beads, native, Backlog.md, Jira status (name). Linear labels already use names; parent/relation refs use identifiers like ENG-431.
