Two scanability fixes found while adding the tall-terminal spacer rows.

Board columns split the width evenly (`boardGeometry`, internal/tui/board.go), at least 28 cells each, so an empty column ("To Do 0") is as wide as one with 79 cards and card titles truncate at about 29 cells at 140 columns. Give an empty column only the width of its header (or of its `No items` line, if wider) and share the rest among columns with cards, each still at least 28 cells. Columns past the right edge scroll as today; how many fit now depends on which columns are in view.

Below 30 rows (`spacedHeight`) there is no spacer, and the view tabs and the unfocused column headers render in the same muted style, so the two rows read as one block. Distinguish the column header without spending a row, keeping NO_COLOR and --high-contrast legible.

## Decisions

1. **Narrowing is not the rejected reflow.** Hiding a blank column changes which columns exist, so `h`/`l` targets and the focused column move when data changes. Narrowing keeps every column in place and in order; a column only changes width when it gains its first card or loses its last. Accept that width change.
2. **Header style.** Unfocused column labels use the default foreground instead of muted; the focused label stays bold and counts stay muted. Use the same style at every height, so there is one board header style rather than one per terminal size. If NO_COLOR still reads as one block, underline the labels.

Rejected for now: hiding all-blank columns (decision 1) and a blank row between board cards (costs a third of visible cards).

## Acceptance criteria

- [ ] On the board, a column with no cards is only as wide as its header, and columns with cards share the remaining width; card titles at 140 columns show more text than before when any column is empty
- [ ] Mouse hit-testing, h/l navigation, and horizontal scrolling follow the new column widths, covered by extending the board cases in internal/tui/mouse_test.go and board_test.go
- [ ] The column header is visually distinct from the view tabs without using an extra row, at every height, under color, NO_COLOR, and --high-contrast
- [ ] docs/tui.md describes both behaviors
