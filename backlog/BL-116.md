The GitHub adapter assigns categories itself (`internal/source/github/github.go` `item`). A project `statuses:` entry for the same key with another category is accepted, but it only changes the display name. So `{key: open, category: backlog}` silently leaves every open issue ready, and agent loops would claim new issues.

Each GitHub status key has one fixed category in every mode, so a project-wide status list can't conflict across GitHub sources:

| Key | Category | When |
| --- | --- | --- |
| `open` | todo | Open issue, plain mode |
| `closed` | done, or canceled for not planned | Closed issue, any mode |
| `unknown` | backlog | Open issue with no mapped status: not in the project, an unmapped option, or (with label statuses) no or several mapped labels |
| option ID or label | as mapped | Open issue with exactly one mapped status |

Validate at config load: a `statuses:` entry for any of these keys must have that category (`closed` accepts done or canceled), and a key must not map to different categories in two GitHub sources. Otherwise fail with a config error that names the key, both categories, and the fix. `bl doctor` reports the same finding.

## Acceptance criteria

- [x] A GitHub source with {key: open, category: backlog} or {key: unknown, category: todo} fails config load with an error naming the key and both categories
  Evidence: go test ./internal/project -run TestGitHubStatusCategories: ok; {open: backlog} and {unknown: todo} fail with 'GitHub assigns open the todo category, not backlog; set category: todo or remove the entry' (file, line, key statuses[0].category).
- [x] A project option mapped to active with a todo status entry fails the same way, as does one key mapped to different categories by two GitHub sources; closed accepts done or canceled
  Evidence: Same test: option opt mapped active + {opt: todo} fails 'source x assigns opt the active category, not todo'; opt active in source x vs todo in source y fails at sources[1].githubProject.options.opt; closed with todo fails ('done or canceled'), closed with canceled loads.
- [x] Matching entries, and entries for keys no GitHub source assigns, still load; bl doctor reports the finding
  Evidence: Same test: matching open/closed(canceled)/unknown/option entries plus unassigned key open-ish load; native-only {open: backlog} loads. bl doctor --json on a scratch repo with {open: backlog} reports config fail with the same message.
- [x] docs/github.md and the design.md register are updated
  Evidence: docs/github.md gains the status key table and load-time rule; docs/design.md adds register D32 (commit 0185137).

- [x] Projects mode open issues not in the project or with an unmapped option read as unknown, backlog, unchanged
  Evidence: go test ./internal/source/github -run TestReconciliation: ok; issue outside the project and an unmapped option both read status unknown, category backlog.
