Project items whose content is a DraftIssue are silently skipped (internal/source/github/projects.go:286, :343), so drafts created in a Projects v2 board never appear in bl. A DraftIssue lives only in the project: it has id, title, body, assignees, createdAt and updatedAt, but no repository, number, labels, comments, or owner/repo#N ref, so it also has no Worklease github claim key. Load drafts from the configured project as items in a backlog-category status (D29: open, never ready), keyed by a stable project-item ref. Promoting a draft out of the draft status calls convertProjectV2DraftIssueItemToIssue with the configured repo, after which the item carries its real owner/repo#N ref and the project status write applies. Title, description, and assignee edits use updateProjectV2DraftIssue; create with --status draft uses addProjectV2DraftIssue. Changes the GitHub model in D24/D34/D35, so it needs a decision register entry.
