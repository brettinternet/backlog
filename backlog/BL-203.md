Reported from another host: setting up linked changes takes an account in user config and, when the origin doesn't resolve on its own, a forge in project config. That's two doc pages. `bl auth login github`, which finds gh and sets up the account's credential, is documented, but nothing pointed the agent to it.

Idea: one command (`bl forge add`, or a `bl init` step) that detects origin, finds or creates the GitHub or GitLab account in user config, signs in, and writes `changes.forges` only when the origin doesn't resolve on its own.

Needs a decision before it is ready: bl doesn't write user config today, and the doctor check and `bl instructions changes` (separate tasks) may make the setup path clear enough without a new command. Revisit after both land.
