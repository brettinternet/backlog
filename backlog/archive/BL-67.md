Mouse equivalent of `<` and `>`: drag a card to another column to change its status. A drop must use the same write and undo path as `>`.

## Decisions

1. **Grouping.** Dragging writes only on a board grouped by status, the only grouping where `<`/`>` edit. On any other grouping (labels and assignees are multi-valued) a press and release is a click.
2. **Threshold.** A drop writes only when the release lands in a different column from the press. Within one column it's a click, and there is no reordering, since rank isn't a board edit. A column is far wider than trackpad jitter, so no time or distance threshold is needed.
3. **Feedback.** While dragging, the target column's header shows `▸` in the accent color. A column whose status the item's source doesn't accept (D35, such as a disallowed Jira transition) shows `⊘`; releasing there writes nothing and the status bar says why.
4. **Whether it earns its place.** Probably not. `<`, `>`, `s`, a sideways swipe, and a click followed by a key already cover it, and showing the card under the pointer would need a floating overlay the TUI doesn't have, so a drag shows only the target header. Promote it only if mouse users ask for it.

## Recommendation

Below the line. Archive it unless someone asks for drag-and-drop. The decisions above are enough to promote it later without another design pass.
