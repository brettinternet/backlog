D19 says MCP tools mirror the CLI operations, but `bl events` has no MCP counterpart. An agent on MCP cannot ask what changed since it last looked, see whether its action's chained hooks succeeded (`hook.finished` outcome), or notice readiness changes, without shelling out.

Add a non-follow `events` tool: `since` and `query` with the CLI's semantics (event terms `changed:`, `hook:`, `action:`, `outcome:` enabled), plus a `limit` and the last returned ID so a caller pages forward with `since`. No follow or streaming; MCP callers poll. Reuse the CLI's reader and filter so the shapes cannot diverge.

## Acceptance criteria

- [x] MCP exposes an events tool taking optional since (exclusive ULID) and query, returning the same data.events shape as bl events --json
  Evidence: go test ./internal/mcp -run TestEventsMatchCLI: MCP events pages (limit 2, unfiltered and changed:status) equal bl events --json data.events; verifier PASS
- [x] An unknown since ID returns the same not-found style error as the CLI; results are bounded (limit with a documented default and a cursor to continue)
  Evidence: TestEventsMatchCLI: unknown since gives not-found from MCP and CLI exit 3; default limit 100 with cursor/more; exhausted cursor returns empty; verifier PASS
- [x] docs/mcp.md and design.md §7 list the tool
  Evidence: docs/mcp.md tool table and Results plus docs/design.md section 7 MCP tools list include events (commit 2c5990f); verifier PASS
