## Why

A transcript is huge, expires, and exists only on one host. A few lines saying "what I did, what I tried, where I stopped" is the part of a session worth reading days later, by a person or by the next agent picking up the item. That matters most when several sessions work one item: implementation, a retry after a lapse, then the PR and review phases. The item's own Summary section is a single final summary, and remote sources can't hold it (GitHub refuses any section but Description). A handoff is per session and works on every source.

The owner also wants optional commit-trailer guidance without `bl` imposing a Git workflow.

## Shape

**Command.** `bl handoff ID TEXT|- --session S [--if-version V]` appends a `session.handoff` event with the D40 `session` object (BL-136) and `handoff: TEXT`. It needs a session (exit 2, `session-required`) but no claim, because PR and review sessions often don't hold one. It writes nothing to the item by default, so `--if-version` only applies in comment mode.

- Text is at most 4 KiB after trimming, with terminal controls stripped on display (D21). Longer text is refused with `invalid-value`, not truncated.
- The newest handoff per session wins when a session records several.
- MCP: `append` accepts `kind: "handoff"` with the required `session` (and the optional `agent`/`agentSession` from BL-136), so no new tool is needed.

**Optional publish.** `history.handoff: local | comment`, default `local`, settable in any config layer. With `comment`, `bl handoff` also appends a comment through the item source's `AppendComment` capability, as `bl comment` does, including D15 version checks and unknown-outcome handling. The comment is the text under one header line naming the agent kind and date. Host, cwd, branch, and session IDs are never published. A source without `AppendComment` records locally and reports `comment: unsupported` in the result. Native comments land in the item file, which is the owner's choice when they configure it.

**Instructions.** `bl instructions workflow` (internal/instructions/workflow.md) asks agents to record a handoff before `done`, before `release`, and at the end of any unclaimed phase on an item (PR follow-up, review), naming the commands to reproduce state and the next step. Keep it to a few lines, matching the existing tone.

**Optional commit trailer.** Project config `history.commitTrailer: KEY` (for example `Refs`). Unset by default, so instructions say nothing about commits. When set, `bl instructions workflow` adds one line: end each commit for an item with `KEY: ID`. Agents can add their own session as a second trailer only if a project asks; don't add that here. BL-103's link derivation should read the same key (add a note to BL-103 when this lands).

**Docs.** Update cli.md (`handoff`), mcp.md (`append` kind), events.md (`session.handoff`), design.md (D40 handoff and trailer lines), and the project and user config schemas.

## Acceptance criteria

- [ ] bl handoff ID TEXT|- --session S appends a session.handoff event with the D40 session object and requires a session but no claim; text over 4 KiB is refused, not truncated
- [ ] MCP append accepts kind handoff with the same session and agent arguments
- [ ] With history.handoff: comment, the handoff is also posted through AppendComment with D15 version and unknown-outcome rules, publishing only the text, agent kind, and date; a source without AppendComment records locally and reports comment unsupported
- [ ] bl instructions workflow asks for a handoff before done, before release, and at the end of unclaimed phases
- [ ] With history.commitTrailer unset, the instructions mention no commit trailer; with it set to KEY, they add one line asking for KEY: ID
