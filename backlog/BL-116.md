The GitHub adapter assigns categories itself (`internal/source/github/github.go` `item`): open is todo, closed is done (canceled when `NOT_PLANNED`), and project options come from `githubProject.options`. A project `statuses:` entry for the same key with another category is accepted, but it only changes the display name. So `{key: open, category: backlog}` silently leaves every open issue ready, and agent loops would claim new issues.

Validate at config load: every status key a GitHub source assigns (`open`, `closed`, mapped option IDs, and mapped labels once label statuses exist) must have a category that source can assign for it (`closed`: done or canceled). Otherwise fail with a config error that names the key, both categories, and the fix. `bl doctor` reports the same finding.

## Acceptance criteria

- [ ] A GitHub source with {key: open, category: backlog} fails config load with an error naming open, todo, and backlog
- [ ] A project option mapped to active with a todo status entry fails the same way; closed accepts done or canceled
- [ ] Matching entries, and entries for keys no GitHub source assigns, still load; bl doctor reports the finding
- [ ] docs/github.md and the design.md register are updated
