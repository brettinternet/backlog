Add brettinternet/backlog issues as a second source, so new GitHub issues show up next to native tasks without feeding agent loops until someone triages them.

Needs the owner: create the `ready` and `in-progress` labels on the repository, create a dedicated disposable repository for live provider tests, and run `bl trust`. The user config account `personal` (gh helper) already exists in `~/.config/backlog/config.yaml`.

Config: add an `issues` GitHub source with `statusLabels: {ready: todo, in-progress: active}`. Add `unknown` (Triage, backlog), `closed` (done), and `ready` (todo) statuses, and reuse `in-progress` as the active key. Set `defaults.source: tasks` so agent `bl new` stays native. Verify readiness with `bl next -n 0`, not plain `bl next`, which shows only the top item.
