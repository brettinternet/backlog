The detail pane is too narrow for diagrams, so Mermaid blocks show only their source. `github.com/AlexanderGrooff/mermaid-ascii` (MIT, about 1.6k stars, release 1.6.2 on 2026-11-17) renders three diagram types as Unicode or ASCII art through a Go API, `render.RenderDiagram(input, *diagram.Config)`, with `MaxWidth` fitting:

- Flowcharts: `graph` and `flowchart` in LR and TD, rectangles only, no diagonal arrows.
- Sequence diagrams: nearly complete, but no activation boxes.
- ER diagrams.

Class, state, Gantt, pie, and other diagram types aren't supported.

Outcome: the language caption on a supported `mermaid` block (from the prerequisite item) also offers to open the diagram. Clicking it, or a key, opens the rendered diagram in a full-screen view that scrolls both ways and closes back to detail. The source stays inline, so the body doesn't grow by the diagram's height. Rendering runs on a worker (D14), cached by block content, width, and theme. Input is size-capped, and a recover turns a library panic into an error. Output passes D21 sanitization, and NO_COLOR drops `classDef` colors.

Before committing to the dependency, confirm `go list -deps ./internal/tui` adds no web server packages (the module's go.mod lists gin for its CLI), and measure a render at the size cap.

Modified files: internal/tui (renderer, view, keys, mouse), go.mod, go.sum, docs/tui.md (Mouse, Rendering, keymap), docs/design.md if the dependency changes a decision.

## Acceptance criteria

- [ ] In detail, the caption of a graph, flowchart, sequenceDiagram, or erDiagram block offers to open it; clicking the caption opens the rendered diagram full screen, and a key documented in docs/tui.md opens the first diagram at or below the top of the viewport
- [ ] The view scrolls horizontally and vertically when the diagram exceeds the terminal, and esc or q returns to detail at the same scroll position
- [ ] Rendering runs off the update loop, cached by block content, width, and theme; input over the size cap, a parse error, or a library panic shows the reason in the view instead of crashing
- [ ] Unsupported diagram types show no open affordance and keep their source
- [ ] docs/tui.md documents the view, its key, and its mouse behavior
