Read the parent epic first. This child gives GitLab merge requests (D43, docs/gitlab.md) the read side of the pull request view. Writes stay GitHub-only, as D43 says for reviews.

## Scope

- **Verdict.** Map `detailedMergeStatus` onto the verdict: `mergeable` reads Ready, `conflict` Conflicts, `need_rebase` Behind, `ci_must_pass` and `ci_still_running` Blocked or Running, `not_approved` Blocked, `draft_status` Draft, and `checking` Checking. Record the mapping table in docs/gitlab.md.
- **Checks.** Head pipeline jobs become checks grouped by stage, with status words, durations, and `allowFailure` marked `optional`. `required` is omitted.
- **Check view.** Job trace through REST `GET /projects/:id/jobs/:job_id/trace` (`read_api`), with the same caps, redaction, and step splitting on GitLab's `section_start`/`section_end` markers.
- Approvals map to Reviews, as today.
- `--detail` JSON uses the same shape, leaving GitHub-only fields empty.

## Tests

- The `detailedMergeStatus` mapping table.
- GitLab trace section parsing, with a fuzz target.
- The fake-server trace fetch under the size cap.

## Acceptance criteria

- [ ] detailedMergeStatus maps onto the verdict as the docs/gitlab.md table records, covered by a table test
- [ ] Head pipeline jobs show as checks grouped by stage, with allowFailure shown as optional
- [ ] The check view shows the job trace split on section markers, with the same caps and redaction and a fuzz target on the parser
- [ ] bl changes --detail uses the same JSON shape, leaving GitHub-only fields empty

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change
