Migrating 12 real Backlog.md projects (hum, noon, wowagent, worklease, goblinhealth, tell, panelctl, after, policyd, policydev, publishwork, unharness; about 2,400 items) with `bl import backlog-md` needed scripted pre- and post-processing in most repos. Each gap below was hit on real data. Scripts and per-repo reports are in /tmp/blmig (stage.sh, fill_dates.py, renumber_slugs.py, dedupe_drafts.py, break_cycles.py, remap_drafts.py, report-*.json).

Cutover
1. `bl import backlog-md --to backlog` cannot cut over in place. It refuses a non-empty `backlog/` (Backlog.md's own directory). For `docs/backlog` sources it writes `backlog/backlog.yaml` nested instead of a root config. Running `bl check` before cutover errors with "source tasks (backlog-md) is not available for native maintenance". Every repo needed a staging copy, an import to a scratch directory, then a hand-written cutover that `git rm`s the Backlog.md partitions, preserves `backlog/decisions` and `backlog/docs`, and copies the native tree into place. docs/import.md describes backup and rollback, but not this flow.
2. The import does not rewrite references to IDs it changes. Drafts are renumbered into the task sequence (and publishwork slugs were renumbered), but `DRAFT-N` / `draft-N` mentions in open items and docs keep the old IDs, and `refs:` paths point at old files. Relative Markdown links in item bodies also break when items move from `docs/backlog/tasks/` to `backlog/` (unharness: about 1,039 links in 117 items, caught by its doc-link test). The report JSON has the mappings, so the import could rewrite links and open-item references, or at least list what dangles. Done items need care because Backlog.md reuses draft numbers.

Refused or silently altered input
3. Archived drafts that reuse an ID (Backlog.md reuses freed draft numbers) are refused as collisions, even though drafts are renumbered anyway (hum draft-001 x3; policyd draft-020/021/022).
4. Empty `created_date: ""` or `''` (and `updated_date`) is rejected instead of treated as missing (publishwork 24 files, unharness 52).
5. Missing `created_date` falls back to file mtime, which is the checkout or copy time. The first Git commit of the source file is the real creation time.
6. Symlinked task files are silently skipped and only counted as skipped (unharness: 145, including active tasks). Follow them or refuse loudly.
7. Non-numeric slug IDs (`pw-some-slug-N`) are refused (publishwork: 130 items). Renumber them like drafts, keeping `legacy_id`.
8. Priorities outside urgent/high/medium/low (`p0`/`p1`/`p2`/`later`) are refused. Map the common ordinal forms, or accept a mapping flag.
9. Dependency cycles that Backlog.md allowed make the result fail `bl check`, even when every item in the cycle is archived and Done (unharness: 6 items, 9 edges). The import should report the cycle and either break it with a note or tolerate cycles among closed items.
10. An unconfigured status (`open`) is silently mapped to todo. It appears only in the JSON mappings and the text report gives no note (publishwork PW-228..231).

Formatting
11. Imported and bl-written files fail Prettier in repos that run it (panelctl, after, publishwork, policydev). `backlog.yaml` uses 4-space indentation, and long frontmatter flow arrays (`refs:`, `files:`) stay on one line past print width. Every repo needed a `prettier --write` pass before its commit hook passed. Emit 2-space YAML and keep the writer stable under Prettier, or document adding `backlog/` to `.prettierignore`.

Query and output
12. `bl ls 'is:open | is:closed'` silently returns 0 items. `|` is not an operator but is parsed as a text term that matches nothing; an unspaced `a|b` gives a usage error. A bare operator-like token should be an error or warning that suggests comma OR (`status:todo,done`).
13. Plain `bl next` with nothing ready prints nothing, which looks like a hang or failure. Print an explicit "no ready items" line (with a hint to use `--explain`).

## Summary

Added `bl import backlog-md --in-place`, which writes the native project into the source repo and removes the committed Backlog.md files. It refuses if the checkout is not a Git checkout, has dirty or unindexed source files, already has native config or an output collision, or contains no items. Native files are written with O_EXCL and rolled back on failure; source files are removed only after every write succeeds.

Import now handles each of these, or refuses with a fix:
- Reused archived draft IDs and slug IDs are renumbered after the prefix IDs, and each keeps its old ID in `legacy_id`.
- Empty dates count as missing. A missing created date comes from the file's first Git commit.
- Symlinked files are followed.
- p0-style priorities are mapped.
- Dependency cycles among closed items are broken with a note. Cycles with an open item are refused.

Mentions, relative links, and refs are rewritten for the new layout; anything ambiguous is reported in `unresolvedReferences`. Prettier-compatible YAML, the bare-`|` query error, and the `next` empty message landed in 3d8ed15.

Commits b690e38 and 3d8ed15 were merged to main in f1eefc9. `task ci` passes. The verifier returned PASS for every criterion. The reviewer found five defects, all fixed and re-run against the reviewer's repro scripts: ignored, symlinked, or nested-repo files passing the dirty check; a stray `config.yml` being deleted; link rebasing that followed symlinks; ambiguous mentions being rewritten; and IDs being rewritten inside URLs.
