Today the only way to learn that a hook or action is broken is to trigger it and read the finished event. A typo in `run[0]`, a placeholder that never expands for this source (`{url}` on native items, `{resource}` without coordination), or an `on:` type that never fires all fail silently or only at run time.

Two small additions, both read-only:

- `bl action NAME ID --dry-run` (and MCP `action` with `dryRun: true`): resolve `when`, expand placeholders against the real item, and print what would run, or exactly why it is disabled. Reuse the existing expansion path so the preview cannot drift from execution.
- A `hooks` check in `bl doctor` covering hooks and actions statically: `exec.LookPath` on `run[0]`, placeholder names against the D21 list, timeout parse, event type against the known set, `before` only on item mutations. Item-dependent expansion stays in the dry-run.

Hooks have no item-free dry-run; the doctor check plus action dry-run covers the common failures. Consider `bl events` replay into a hook dry-run only if this proves insufficient.

## Acceptance criteria

- [ ] bl action NAME ID --dry-run prints the expanded argv, cwd, and environment names, or the refusal reason, and runs nothing, appends no event, and needs no --yes
- [ ] bl doctor gains a hooks check: every trusted hook and action has a resolvable run[0] on PATH, only known placeholders, a valid timeout, and a known on event type; failures name the hook and the fix
- [ ] Untrusted declarations are reported as inert, not executed or probed
- [ ] docs/cli.md and docs/automation.md are updated, including the doctor check count

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change

## Notes

Before implementing, check what config load already rejects (placeholder names, event types, phase, timeout) and have doctor report only what load does not, so the two never disagree.
