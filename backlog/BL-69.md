Found while writing `examples/16-mcp` (9a18830).

1. **MCP results use Go field names.** `next`, `query`, `show`, and write results serialize `model.Item` directly (`internal/mcp/server.go:76`, `:81`, `coordination.go:64`), so items read `{"Project":"","Ref":{…},"Title":…,"Version":…,"BlockedBy":[{"source":"","id":"BL-1"}]}`. `bl show --json` and the event log use lower camel case (`title`, `version`, `blockedBy`), and docs/mcp.md tells agents to pass back `version`. Fix this before the first release; afterward, renaming is a breaking change for every agent. Use the CLI's JSON shape (or the event log's item shape), and pick one for all three. Edge targets also show `source: ""` for local refs; resolve them to the item's source.
2. **Concurrent MCP writes without `version` can return `conflict`.** A client that sends `update BL-2 {status: in-progress}` and `criteria BL-2 check 1` without waiting gets `conflict: expected version does not match current content` for the update, although it passed no version. docs/mcp.md says `version` is optional and only a stale one conflicts. Either serialize writes to one item inside the server, or retry an implicit-version write once against fresh content. Repro: pipe both `tools/call` frames to one `bl mcp` before reading responses.
