Read the parent epic's "Check" layout, Writes, and "Safety and budgets" sections first. They are the settled design. This child answers "why did this job fail" without leaving bl.

## Scope

- **Check view.** `enter` on a check, in Overview or a Merge reason, opens it one level under Overview. `backspace` returns to that entry. The header shows name, state, duration, and start age, followed by Steps, Annotations, and Log or Output.
- **Detail read.** One GraphQL read by check run node ID for `steps(first:50)`, `annotations(first:50)`, and `summary`. It runs on the detail worker through the account queue, is redacted and stripped (D21), and is cached by check run ID once the run completes. A running check isn't cached.
- **Log excerpt.** For a completed failed GitHub Actions job (check run `databaseId` is the job ID), fetch REST `/actions/jobs/{id}/logs` when the check view opens. Never send credentials to the redirect host. Stream lines, holding only the last 100 (each capped at 2 KiB). Stop at the first `##[error]` line, or at the end; abort past 32 MiB and offer `O`. Strip timestamps, and color `##[error]` and `##[warning]` lines. Cache the excerpt per check run and attempt under the state directory, redacted. Without Actions read (BL-179), or while the job runs, the Log line says why and `O` opens the job.
- **Keys.** `yl` copies the excerpt. `O` opens the check, step, or annotation URL.
- **Other checks.** Non-Actions check runs show output title and summary as Markdown. Commit statuses show their description.
- **Placeholders.** While a check is shown, actions can use `{check.run}` (the Actions run ID) and `{check.url}`; an action naming one runs only from a check view (docs/automation.md). Ship `gh run rerun {check.run} --failed` as an example.
- **Agents.** `--detail` and MCP `detail` add, for each of the first five failing runs, its `steps`, `annotations`, and `log` (the excerpt) or `logUnavailable` with the reason.

## Tests

- Excerpt extraction (100-line window, first error line, timestamp strip, line cap) with a fuzz target, since logs are untrusted input.
- The fake server asserts that the redirect request carries no `Authorization` header, that the 32 MiB abort holds, and that a secret in the log is redacted in the view, the cache, and `--detail` JSON.
- TUI routing: `enter` on a check, and `backspace` returning to the entry.
