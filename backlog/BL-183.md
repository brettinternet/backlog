Read the parent epic first, especially its Scope rule. This child gives GitLab merge requests (D43, docs/gitlab.md) the read side of the pull request view. Resolving threads stays GitHub-only, as D43 says for reviews. Draft until a GitLab project needs it.

## Scope

- **Verdict.** Map `detailedMergeStatus` onto the verdict: `mergeable` reads Ready, `conflict` Conflicts, `need_rebase` Behind, `ci_must_pass` and `ci_still_running` Blocked or Running, `not_approved` Blocked, `draft_status` Draft, and `checking` Checking. Record the mapping table in docs/gitlab.md.
- **Checks.** Head pipeline jobs become checks with state words and durations. A failing job with `allowFailure` doesn't block.
- **Check view.** The job trace through REST `GET /projects/:id/jobs/:job_id/trace` (`read_api`), with the epic's excerpt rule (last 100 lines), caps, and redaction.
- Approvals map to Reviews, as today.
- `--detail` JSON uses the same shape, leaving GitHub-only fields empty.

## Tests

- The `detailedMergeStatus` mapping table.
- The fake-server trace fetch under the size cap, with the excerpt fuzz target extended to GitLab traces.

## Acceptance criteria

- [ ] detailedMergeStatus maps onto the verdict as the docs/gitlab.md table records, covered by a table test
- [ ] Head pipeline jobs show as checks with state and duration, and a failing allowFailure job does not block
- [ ] The check view shows the job trace excerpt with the same caps and redaction, covered by the excerpt fuzz target
