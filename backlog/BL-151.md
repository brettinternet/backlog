Phase 6 of BL-103: render CodeTour .tour files an action or hook writes and returns through BL_RESULT, with a pinned head SHA and optional criterion index per step, stored in XDG state per change and shown stale when the head moves. ]t and [t step through the tour in the change view. See the Guided tours section of BL-103.

## Acceptance criteria

- [ ] An action or hook that returns a .tour path through BL_RESULT stores a copy in XDG state for the item's change; bl never generates a tour

- [ ] A tour is CodeTour .tour JSON (steps with file, line, and Markdown description) plus a pinned head SHA and an optional criterion index per step, and an invalid tour is refused with the reason

- [ ] In the change view, `]t`/`[t` step through the tour, with each step's narrative and cited criterion above its hunk in the Diff

- [ ] A tour whose pinned head differs from the change's head shows stale rather than landing on other lines

- [ ] Tour text passes D21's control-sequence stripping, and docs/automation.md documents the tour result

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change
