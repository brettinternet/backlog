Change terms filter by state, not stage: a local branch or worktree is also `open` (internal/changes/link.go:331), so `change:open` mixes branch-only work with pull requests and there is no way to list "items with a PR". Add a stage term (e.g. `has:pr` or `change:pr`) so users and views can filter to items with a linked pull request or merge request.

## Acceptance criteria

- [x] A query term matches items with a linked pull request or merge request and not items with only a worktree or branch
  Evidence: TestFields (go test ./internal/query): has:pr matches a change with PR and not a branch-only open change; hooks refuse has:pr. Live: bl ls 'category:active has:change' lists BL-186/192/193 (worktrees), 'has:pr' lists none; temp project with --ref .../pull/7 matches has:pr, the other item matches -has:pr.
- [x] docs/query.md and docs/changes.md document the term; design.md D43 updated if it changes the decision
  Evidence: docs/query.md has table and Notes explain has:pr vs change:open; docs/changes.md Queries row lists has:pr; design.md D43 query list adds has:pr (a3d3107).
