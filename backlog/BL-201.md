Reported from another host: `bl doctor` passed with no forge configured. Its accounts check covers only sources. With origin on github.com and no GitHub account, engine.forges returns nothing (internal/engine/changes.go), and nothing says why linked pull requests never appear. It returns nothing too when two accounts match the host.

Outcome: `bl doctor` gains a forges check, and `--json` carries the same facts.
- For each resolved forge it shows type, host, repo, account, and whether it is explicit (`changes.forges`) or implicit (origin). It reads one page of pull requests with checks and closing references, reporting `ok`, or which part the token can't read (pull requests, checks, closing references), as `fail` for pull requests and `warn` for the rest. It also reports the cache's sync state: pull requests kept, last refresh, and whether older ones are still being read.
- With a GitHub or GitLab origin and no forge, it warns with the reason: no account for that host, naming the account to add with a minimal user config snippet and `bl auth login`, or several accounts, naming them and the `changes.forges` entry that picks one.
- An explicit forge that can't be built (untrusted, unknown account) fails with that reason.
- A project whose origin isn't GitHub or GitLab, or that has no origin, reports the check skipped.

Non-goals: writing config (a separate draft covers setup), checking GitLab beyond the same read.

Modified files: internal/cli/doctor.go, internal/cli/read_test.go or the existing doctor tests, internal/engine/changes.go (expose resolution with its reason), docs/cli.md (bl doctor), docs/changes.md.
