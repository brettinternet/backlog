Writing a tour costs agent tokens, so tours stay opt-in and the project decides. A backlog.yaml setting turns them on, chooses whether agents are nudged (the workflow suggests a tour) or required (done refuses without a current tour), and narrows which changes need one, for example only pull requests. With the setting absent, nothing mentions tours beyond the tours topic itself. Depends on the store-time step check so required tours can't be satisfied by tours that render nothing.

## Acceptance criteria

- [ ] A backlog.yaml tours setting with mode off (the default), suggest, or require, and a change filter (for example pull requests only); invalid values are refused at config load with the reason
- [ ] With mode off or the setting absent, bl instructions workflow, next, and done output don't mention tours
- [ ] With suggest, bl instructions workflow and the done response tell the agent to write a tour for each matching change at its head, citing criteria
- [ ] With require, done refuses while a matching linked change has no tour for its current head, naming the change and the command to store one
- [ ] Changes outside the filter are never nudged or required
- [ ] docs/format.md (or the config doc), bl instructions tours and workflow, and design.md describe the setting
