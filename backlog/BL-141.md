## Why

The owner's PR-phase work runs through shared skills (pr-babysit, pr-babysit-loop, pr-review) that never claim a backlog item or call `bl`, so those sessions would be missing from item history (BL-135). The skills live outside this repository, so this needs the owner (`human`).

## Shape

After BL-137 ships `bl handoff`, add one step to each shared skill that works a PR tied to a `bl` item: when the PR's head branch starts with an item's branch prefix (`bl-12-…`) and the repository has a `backlog.yaml`, record a handoff at the end of the pass with `bl handoff ID - --session <harness session ID>`, passing the harness's own session ID (for example `CLAUDE_CODE_SESSION_ID`). Use the snippet BL-137 documents. Skip silently when the repository has no `bl` backlog.

- [ ] pr-babysit, pr-babysit-loop, and pr-review record a bl handoff for the linked item at the end of a pass in bl repositories, and do nothing elsewhere
- [ ] A PR-phase session for a bl item appears as its own session with a handoff in bl history
