### Why

Pressing `S`, `D`, `C`, or picking an active status in the TUI fails with `session-required` unless the user launched it with `--session` or `BL_SESSION`. A person browsing their backlog shouldn't need to know Worklease sessions exist.

### Shape

- With no `--session`, `BL_SESSION`, or `WORKLEASE_SESSION_ID`, the TUI (`bl tui` and bare `bl` on a terminal) coordinates as session `tui`. Explicit sources still win.
- One fixed name, not per process or per TTY: Worklease recovers a held claim or a pending acquire only through the same selector, so reopening the TUI anywhere must resume it. Handles are already scoped by the Worklease home and control root, and `agentId` (`user@host`) still identifies the holder.
- Every TUI window shares the session. That is one person acting, so it is correct; simultaneous operations can return `handle-in-use`.
- CLI commands and MCP keep requiring an explicit session; `next --claim` still refuses an unscoped one.
