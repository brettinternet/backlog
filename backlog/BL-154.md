Phase 3c of BL-103: read-only pull request detail in the change view. Overview lists each check and commit status with its link and each reviewer with their state; a Conversation tab shows comments and review threads. Agents get failing check names from `bl changes --json` without calling `gh`. Detail is fetched for the item shown through the account queue, not on every list refresh, with the read permissions BL-147 granted. BL-150 adds writes.

## Acceptance criteria

- [ ] Overview shows a pull request's description, each check run and commit status with its name, state, and link (`O` opens the one under the cursor), and each requested or submitted reviewer with their state
- [ ] Conversation lists the pull request's comments and review threads with author, file, line, and resolved state, unresolved first
- [ ] The Changes entry shows the unresolved thread count beside the review decision
- [ ] bl changes ID --json and MCP changes include each check's name, state, and URL and the unresolved thread count, and TestEventsMatchCLI covers them
- [ ] Detail is fetched on a worker through the account's request queue for the item shown and cached by head SHA; the pull request list refresh doesn't fetch it, and a failed fetch keeps the cached detail marked stale
- [ ] Description, comment, and check text pass D21's control-sequence stripping and provider redaction before display or caching

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change
