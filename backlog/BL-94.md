After a lease expires, reacquiring with the same session returns `uncertain`, then `next --claim` fails with "session ownership unresolved; inactive retained handle; explicit Worklease recovery required" (exit 6). An agent following AGENTS.md (never switch sessions, never bypass) is stuck. Observed on BL-91 (2026-10-26): `worklease status` showed the claim `active:false` and expired, not pending; `worklease handle archive --session S` (authority mutation none) then a plain `bl claim` acquired. When the retained handle holds only an expired, non-pending claim, bl should archive it and acquire again; pending or recovery state must still refuse.
