### Why

Native sources on Windows fall back to `watch_other.go`, which means 50 ms stat polling. At 10k–50k items that breaks the §11 idle budget and adds latency to external edits.

### Shape

Add `internal/source/native/watch_windows.go` with one `ReadDirectoryChangesW` handle per watched directory, using overlapped I/O and cancelled by context. Watch file name, last write, and size changes. These cover renames and in-place edits, so Windows doesn't need the stat sweep. On a notification buffer overflow, do a full rescan. If opening the watch fails, fall back to polling the way `EMFILE` already does, and never treat a failed refresh as proof of deletion.

The owner accepted CI in place of a Windows 10k timing; reference host TestWatchMeasurement: create 66 ms, rename 41 ms, delete 51 ms.
- [x] A notification buffer overflow triggers a full rescan that misses no change, and a failed watch falls back to polling without treating a failed refresh as a deletion
  Evidence: CI run 40990424867 on b140ce3: Go CI windows-latest, macos-latest, ubuntu-latest success; TestWindowsWatchOverflowSignals (5,000 creates past the 64 KiB buffer: Wait signals, watch stays usable, cancel ends it) and TestWindowsWatchOpenFailurePolls pass; the signal reloads via Load, which re-lists the directory. Fallback modes open-failed/watch-failed (errPollingOnly) and TestWatchedDirectoryReplaced pass on all three OSes; watchStats keeps a previous stat on a failed Lstat instead of dropping it.
- [x] Idle for 1 h at 10k items stays within 2% of one core with no goroutine or heap growth, measured on a Windows host and recorded in docs/benchmarks.md
  Evidence: Owner accepted windows-latest CI in place of a 1 h Windows host soak (as BL-105); CI run 40990424867 on b140ce3: Go CI windows-latest, macos-latest, ubuntu-latest success. Windows idle cost by design: WaitForMultipleObjects INFINITE (no wakeups) plus one directory stat per 2 s. docs/benchmarks.md Native watcher section records the harness, reference-host results (1.77% of one core, goroutines 6->6, no heap growth), and that Windows is CI-only.
- [x] docs/tui.md describes the Windows watcher
  Evidence: docs/tui.md describes the Windows watcher: one overlapped ReadDirectoryChangesW handle per source, no per-item sweep, overflow signals a rescan, open/watch failure or a moved/replaced directory (2 s identity check) falls back to 50 ms polling. Merged in adce82a/11e58b7.
