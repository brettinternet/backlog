Phase 2 of BL-103: a GitHub forge that fetches pull requests through the account queue and links them to items with state, checks, and review. See BL-103, docs/changes.md, and docs/github.md#linked-changes.

## Acceptance criteria

- [x] A GitHub forge fetches pull requests through the account host queue into a per-repo cache with an updated cursor, and a failed refresh keeps the cached pull requests marked stale
  Evidence: Forge.PullRequests (source/github/pulls.go) fetches through the account's request queue into a per-repo cache advanced by an updatedAt cursor. TestForgePullRequests (go test ./internal/source/github) passes: decodes state, review, checks, and closing references, keeps the token out of the body and the cache file, refreshes checks without moving the cursor, and returns cached PRs with an error when a refresh fails; TestLinkStates shows them stale.
- [x] A pull request links by head branch, whole-word ID in the title, a closing keyword in the body, or the provider closing references, and shows state, checks, and review decision
  Evidence: TestLinkStates links PRs by head branch (#45), title (#46), closing keyword (#47), and provider reference (#50), with state, checks, and review; go test ./internal/changes passes.
- [x] change:, checks:, and review: match linked pull requests, and hook conditions refuse them
  Evidence: TestFields: change:merged, checks:failing, and review:approved match a linked change and their opposites don't; hook parsing refuses has:change, change:, and checks:.
- [x] docs/github.md names the read App permissions the forge needs as an owner step
  Evidence: docs/github.md#linked-changes names Pull requests, Checks, and Commit statuses: read on bl-cli-read as an owner step; tracked as BL-147.
