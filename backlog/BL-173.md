Some teams keep their backlog as OpenSpec change folders (`openspec/changes/<name>/` with `proposal.md`, `design.md`, spec deltas, `tasks.md`). Let `bl` show them without adding a core backend: OpenSpec is a spec tool, not a tracker (§2 non-goal: docs manager), and has no IDs, priority, assignees, or edges, so a native backend would mostly show empty fields.

## Proposal

An adapter on the external protocol (docs/external-adapter-protocol.md, BL-42):

- ID: change folder name; archived `YYYY-MM-DD-<name>` folders map back to `<name>`.
- Title: first heading of `proposal.md`, else the folder name.
- Description: `proposal.md`. Acceptance criteria: `tasks.md` checkboxes.
- Status: active with no checked tasks = todo, some checked = in progress, under `changes/archive/` = done.
- Version: content hash of the change folder's files.
- Coverage: complete (local scan).

## Out of scope

- A core OpenSpec backend or design.md §10 row.
- Proposing, applying, or archiving changes through `bl`; that stays in `openspec`.

## Open questions

- Ship it under `examples/`, `cmd/`, or a separate repo?
- Read files directly or shell out to `openspec list --json`/`show --json` (adds a Node dependency, but survives format changes)?
- Is there enough demand? Wait for a request before starting.

## Acceptance criteria

- [ ] An external adapter lists each active and archived OpenSpec change as an item and passes `bl adapter check`
- [ ] An archived change keeps the same item ID as when it was active, with the archive date prefix stripped
- [ ] Status maps proposed/in-progress/archived from folder location and tasks.md progress; tasks.md checkboxes appear as acceptance criteria
- [ ] The adapter is read-only unless check-criterion writes to tasks.md are proven safe with ExpectedVersion
- [ ] Docs say where the adapter lives and how to configure it as a `type: external` source

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change
