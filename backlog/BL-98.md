Follow-up to BL-88, which made sprints read-only. Allow `bl set ID sprint=current|next|none|<key|name>` and a TUI sprint picker, resolved against the source's sprint catalog. Linear: issueUpdate(input:{cycleId}). Jira: POST /rest/agile/1.0/sprint/{id}/issue to move issues into a sprint, and backlog/issue to remove them. Item versions leave out the sprint (D31), so the write preflight must re-read the current sprint explicitly rather than rely on the version check. Same host, so no trust renewal.

## Acceptance criteria

- [ ] bl set ID sprint=VALUE changes the sprint for Linear and Jira items; current/next/none and names resolve via the catalog; unknown values and non-capable sources are refused
- [ ] The TUI offers a sprint picker (catalog names, current and next first) with optimistic update and rollback on failure
- [ ] Writes never replay automatically; a concurrent provider change is detected before dispatch; httptest fakes cover success, conflict and refusal
- [ ] design.md D31, linear.md, jira.md, cli.md and tui.md document the write path
