Claims last about 15 minutes and renew only by manual heartbeat. On BL-91 (2026-10-26) the lease lapsed while a blocking `task ci` ran, so the item showed as abandoned and needed recovery. Choose and document one approach: run long gates under `worklease run` (automatic renewal), heartbeat before long commands in the agent instructions, or a bl-side wrapper that renews while a command runs.

## Acceptance criteria

- [x] A claimed loop running task ci longer than the TTL keeps its claim
  Evidence: Real Worklease, isolated WORKLEASE_HOME, WORKLEASE_TTL=6s: `bl next --claim --start` then `bl heartbeat -- sh -c 'sleep 20; exit 7'` returned 7 after 21s, and `worklease list` plus `bl heartbeat` still showed the claim renewed; unwrapped control `sleep 10` lapsed (`bl heartbeat` exit 6, no verified held claim). Regression test TestHeartbeatRenewsWhileCommandRuns passes. This loop ran `task backlog:cli -- heartbeat --session SESSION -- task -d "$PWD" ci` from the worktree on main 881fb8f: exit 0, claim renewed after.
- [x] bl instructions workflow and AGENTS.md describe the chosen approach
  Evidence: `task backlog:cli -- instructions workflow` on main 881fb8f prints `bl heartbeat --session loop-a -- task ci` with the wrap rule; AGENTS.md backlog section documents `task backlog:cli -- heartbeat --session SESSION -- task -d "$PWD" ci` (verified: without -d the child runs in primary).

## Plan

Chose a bl-side wrapper: `bl heartbeat -- COMMAND` renews at half the remaining lease while the command runs. Rejected `worklease run --resource` (acquires its own claim under a new session, conflicting with the loop's held claim) and heartbeat-before-command (fails once a gate exceeds one TTL). `worklease exec` renews too, but holds the handle lock, captures output, caps at 1h, and must run from the control root.

## Summary

Added `bl heartbeat -- COMMAND` (881fb8f): renews first (refusing to run on failure), runs the command with bl's streams, renews at half the remaining lease, warns and retries sooner on failure without stopping the command, stops after lapse, and exits with the command's status (128+signal when killed). Documented in bl instructions workflow, AGENTS.md, docs/cli.md, design.md §9, development.md. Verified with a real 6s-TTL Worklease run, a regression test, and `task ci` on the final commit. Review: one self-review pass, no defects.
