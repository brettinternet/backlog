An agent can store a tour but can't see it afterwards: bl show and bl changes don't mention tours. Add a read path so an agent can confirm what it stored and whether it's stale, and so automation can skip changes that already have one.

## Acceptance criteria

- [ ] bl tour ID with no FILE prints the stored tour for each linked change, with its ref and whether it's stale; --json prints the stored tour JSON plus change, ref, and stale
- [ ] bl changes ID --json reports per change whether a tour exists for its head (tour: {ref, steps, stale}) without reading it on the TUI update loop
- [ ] The MCP tour tool reads when no tour is given, matching the CLI's JSON
- [ ] An item with no stored tour reads as empty, not an error
- [ ] docs/cli.md, docs/mcp.md, and bl instructions tours describe reading
