The list change column (e.g. `⇡#45 ✓`) is how users spot items with a pull request while scanning. As the pane narrows it drops early (after updated, assignee, children, together with criteria; docs/tui.md Layout), before blockers and claim, so the PR signal disappears first on narrow terminals. Revisit the drop order or keep a compact form (stage glyph plus verdict) so linked pull requests stay visible.

## Acceptance criteria

- [ ] At widths where blockers and claim still show, a row with a linked pull request still shows its stage and merge verdict
- [ ] docs/tui.md drop order updated to match

## Definition of done

- [ ] task ci passes on the final commit
- [ ] Every checked acceptance criterion has --evidence naming the verification command and its result
- [ ] Substantial changes had an independent verifier pass that returned PASS for every acceptance criterion
- [ ] The diff stays within the task's modified-file list, or Implementation Notes justify the deviation
- [ ] No test was deleted, skipped, or weakened
- [ ] User-visible behavior changes are reflected in README.md or docs/ in the same change
