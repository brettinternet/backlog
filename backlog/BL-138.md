## Why

The owner wants to reopen the agent sessions that recently worked an item, straight from the item: resume where an implementation stopped, or reopen the PR-phase session to address review feedback. How to resume depends on the person's agent and terminal setup, for example a new Herdr pane in the same tab as `bl`. So it's configured once in user config, not per project.

## Shape

**Config.** BL-136's `agents:` entries gain `resume`, optional `fork`, and optional `detach`, from built-ins and user config only (never repository layers, so a cloned repository can't plant a command):

```yaml
agents:
  claude:
    session: CLAUDE_CODE_SESSION_ID
    resume: [claude, --resume, "{agentSession}"]
    fork:   [claude, --resume, "{agentSession}", --fork-session]
  pi:
    session: PI_SESSION_ID
    resume: [pi, --session, "{agentSession}"]
    fork:   [pi, --fork, "{agentSession}"]
```

Verify each built-in flag against the installed CLI before shipping. On 2026-10-29: `claude --help` lists `--resume <id>` and `--fork-session`; `pi --help` lists `--session <path|id>` and `--fork <path|id>`; `codex resume [SESSION_ID]` exists, with no fork verified, so leave `fork` unset there.

**Placeholders.** Resume and fork argv and `cwd` accept the D21 item placeholders plus `{agentSession}`, `{session}`, `{agent}`, `{cwd}` (the recorded checkout), and `{host}`. Every expanded value passes the D21 checks, and a failure refuses the run. They run with no shell and in the D21 minimal environment, the same as actions. Extend D21's placeholder list in design.md for agent commands only.

**Selecting resume or fork.** If the item is in a closed category and `fork` is set, run `fork`, so a finished session's transcript isn't extended against code that has moved on. Otherwise run `resume`. An explicit `--fork` or `--resume` (or the TUI's alternate key) overrides this.

**Checks before running.** Each check refuses with a reason the TUI shows on the row and the CLI reports as a refusal (exit 4, with a `reason` naming which check failed):

- `other-host`: the recorded `host` differs from this host.
- `checkout-removed`: the recorded `cwd` isn't an existing directory. Agents such as Claude Code look up transcripts by the directory they ran in, so don't fall back silently. Name the path.
- `live`: the session's claim on this item is active (held and not expired). Two processes would write one transcript. Once BL-142 lands, the refusal lists the session's live contact channels: a live session is messaged, not resumed. Herdr or Claude Code reporting the agent as running counts as live even after the claim has ended.
- `no-agent-config`: there's no agent kind, or its entry has no `resume`.
- A TUI `tui:` session (D39) is never resumable and never listed as resumable.

A transcript the agent has already expired can't be detected generically. The command's failure shows like a failed action (exit status plus stderr tail), and the row stays.

**Running.** The command runs in the recorded `cwd`. Like a non-detached action, it suspends the TUI the way `$EDITOR` does. With `detach: true`, it runs in the background and returns at once, for terminal multiplexers. It ends in an `action.finished` event with name `resume` or `fork` and the `session` object, so hooks can chain.

**Surfaces.**
- TUI: in the History tab (BL-139), session rows show resumability. One key resumes or forks the row under the cursor, and an alternate key runs the other command. Choose keys consistent with the tui.md keymap and document them. The `!` action menu lists "Resume AGENT · AGE" for each resumable session of the selected item, so this works before BL-139 lands and from the list view.
- CLI: `bl resume ID [SESSION] [--fork|--resume]`. With one resumable session, `SESSION` is optional. With several, it's required in non-interactive use, and the refusal lists the candidates.
- MCP: none. Resuming opens an interactive agent for a person, and an agent shouldn't spawn another agent's session.

**Herdr example** (docs/automation.md or tui.md). Herdr's `pane split` doesn't launch a command, so the example splits, then runs, with values passed as positional arguments and not interpolated into the script. Check the output shape of `herdr pane split` (and whether it can emit JSON) before documenting:

```yaml
agents:
  claude:
    detach: true
    resume: [sh, -c, 'p=$(herdr pane split --current --direction right --cwd "$1") && herdr pane run "$p" claude --resume "$2"', sh, "{cwd}", "{agentSession}"]
```

**Docs.** Update design.md (D40 resume, D21 placeholders), tui.md (History keys, the `!` menu), cli.md (`resume`), the user-config schema, and the automation examples.

## Acceptance criteria

- [ ] User config agents.KIND.resume, fork, and detach run with the D21 placeholders plus agentSession, session, agent, cwd, and host, without a shell, in the recorded cwd; repository layers can't set them
- [ ] Closed items fork when fork is configured and open items resume; --fork and --resume override
- [ ] Resume refuses other-host, checkout-removed (naming the path), live (active claim), and no-agent-config with a visible reason; TUI tui: sessions are never offered
- [ ] The TUI ! menu lists resumable sessions for the selected item, and bl resume ID [SESSION] works from the CLI and lists candidates when ambiguous
- [ ] A resume or fork ends in action.finished with name resume or fork and the session object; a failed agent command shows its exit status and stderr tail and keeps the row
- [ ] Built-in claude and pi commands are verified against the installed CLIs, and docs show a working Herdr new-pane example verified in a Herdr tab

- [ ] When BL-142 is done, the live refusal lists the session's contact channels, and an agent reported running by a contact channel counts as live
