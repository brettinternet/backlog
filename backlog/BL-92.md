When a Linear blocker is trashed, Linear doesn't bump the blocked issue's updatedAt (measured live in BL-90). The minute change window sees the blocker as trashed and marks it archived, and the default view then drops it (internal/engine/read.go:106). The blocked issue keeps its cached BlockedBy link, which now points at a missing item, so readiness reports blocker-unknown (internal/engine/readiness.go:157-199). The issue stays Unknown instead of ready until the hourly reconciliation re-reads it.

Options to weigh, which may need a design.md decision:
- Engine: treat a blocker the snapshot knows is archived/trashed as resolved instead of unknown. This is source-agnostic, but it changes readiness semantics; check the design.md decision register and the native-format archive semantics first.
- Linear adapter: when the change window sees a newly trashed issue, also re-read the issues it blocked (for example from the cached reverse index, or from its archived relations via includeArchived). This keeps the change Linear-only, at the cost of extra detail reads.
