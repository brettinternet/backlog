## Why

A tab's label stopped matching its rows. In a Linear project the Mine tab listed other people's and unassigned items, because:

1. `is:mine` alone suppresses the implicit `is:open`, so done items appear.
2. `fd` (and `fr`) replace every `is:` term with their own value, so `fd` turns `is:mine` into `is:open,closed` and the tab shows everything.
3. Session state restores each tab's edited query on every launch, with nothing on screen to show it differs from the definition. A built-in tab never changes config, so a broken edit persists forever.

## Shape

- Implicit `is:open` applies unless an `is:` term selects a state (`mine`, `claimed`, and `pending` don't). One helper in `internal/query` replaces the three copies in the CLI, MCP, and projector.
- `fd` and `fr` toggle only their own term and keep other `is:` terms.
- Session state keeps the active tab and selections, not tab definitions: query, layout, and columns reset to the declared view on launch. `ctrl-s` saves an edit you want to keep.
- A tab whose query or layout differs from its definition shows a mark.

## Acceptance criteria

- [ ] is:mine (or is:claimed, is:pending) alone still adds the implicit is:open in the TUI, bl ls, and MCP query
- [ ] fd and fr toggle only their own term and keep other is: terms such as is:mine
- [ ] Relaunching the TUI resets every tab query, layout, and columns to its definition while keeping the active tab and selections
- [ ] A tab whose query or layout differs from its definition shows a mark
- [ ] docs/tui.md and docs/query.md describe the new behavior
