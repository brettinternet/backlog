Two scanability fixes found while adding the tall-terminal spacer rows.

Board columns split the width evenly, so an empty column ("To Do 0") is as wide as one with 79 cards and card titles truncate at about 29 cells at 140 columns. Give an empty column only its header's width and share the rest among columns with cards.

Below 30 rows there is no spacer, and the view tabs and the column header render in the same muted color, so the two rows read as one block. Distinguish the column header without spending a row (for example underline, or a different weight), keeping NO_COLOR and --high-contrast legible.

Rejected for now: hiding all-blank columns (reflows the list when data changes, against the no-shift rule) and a blank row between board cards (costs a third of visible cards).

## Acceptance criteria

- [ ] On the board, a column with no cards is only as wide as its header, and columns with cards share the remaining width; card titles at 140 columns show more text than before when any column is empty
- [ ] Mouse hit-testing and h/l navigation follow the new column widths, covered by the existing board mouse test
- [ ] Below 30 rows the column header is visually distinct from the view tabs without using an extra row, under color, NO_COLOR, and --high-contrast
- [ ] docs/tui.md describes both behaviors
